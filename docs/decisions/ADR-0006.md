### 24.6 Phased plan (cross-stream)

This synthesizes §§24.2–24.5 into a buildable sequence. Each phase ships
shippable value; phases are roughly independent except where noted.

| Phase | Theme | Includes | Effort |
|---|---|---|---|
| **P1** | Eval (closes CLI MVP) | §24.5 | ~2 d |
| **P2** | Pack composition contract + MCP requirements | §24.3 (provides/requires/optional + encapsulation + policy-by-capability + cross-pack subgraphs + incident-pack migration) + §24.13 `requires.mcp_servers` manifest extension. **Schemas + events are reserved slots only — Bus + subscribers land in P3 per §24.10.** | ~6.5 d |
| **D2 — Demo restructure** | Minimum-viable §24.19 + §24.20 substrate, 4 operator packs extracted from existing tested code, incident pack cleaned to §24.20 conformance (3 templates kept, 6 retired, `code/` deleted), E2E demo via subgraph composition | §24.21 detail. Substrate-light (OP1–OP4 light + SCH1/2/4 light + inprocess routing): ~4.5 d. Operator packs (clickstack/git/blast-radius/postmortem): ~2.5 d. Incident pack cleanup + tests: ~3 d. Demo integration + storyboard + recording: ~2 d. | **~12 d** |
| **P3** (post-D2) | §24.19/§24.20 remainder + Temporal handler + Bus Tier 1 + template lifecycle + MCP layer + §24.14 Tier 1 + §24.15 platform self-observability | §24.2 additive Temporal handler (~3 d), §24.10 Bus Tier 1 + §24.3.7 closure (~3 d), §24.11 content-addressed versioning + skill-tag resolution + regression eval MVP (~6 d), §24.13 doctor [mcp_servers] + `integrations/custom/` + Bifrost reference (~1.5 d), **§24.14 C8 event taxonomy + C4 approval-gate primitive + C3-basic cost surface (~5–7 d)**, **§24.15 O1 + O2 + O3 (~4–6 d)**, **§24.19/§24.20 remainder per §24.21.7: OP5–OP10, SCH3, SCH5, PRF1–3, C8b, §24.20.21 DX polish, universal node-type renames (~15–18 d)**. | ~37.5–44.5 d |
| **P4** | Storage Phase 1 + few-shot library + MCP catalog + §24.14 Tier 2 primitives + §24.17 pack lockfile | §24.4 Protocols + SQLite/sqlite-vec for runs/events/memory/RAG + §24.12 Form 3 few-shot library on memory store + §24.13 `mcp_catalog.toml` + `cairn mcp catalog/install/status` CLI, **§24.14 C6 artifact lineage + C7 object storage tier + C1 external-job primitive + C10 ExtJob→Bus emission (~14–19 d)**, **§24.17 `[requires.packs]` + CompiledPack + resolver + `cairn lock` + doctor [lockfile] + visualize --lock (~3–4 d)**. | ~23.5–29.5 d |
| **P5** | Storage Phase 2 + Bus Tier 2 + suggestion engine + MCP scaffold | §24.4 Postgres + pgvector impl + §24.10 PostgresBus + §24.12 Form 4 suggestion engine + `suggestions` table + `cairn suggest` CLI + optional GitHub PR adapter + §24.13 `cairn init mcp-server` scaffold. | ~8.5 d |
| **P6** | Storage Phase 3 | §24.4 sessions / approvals / budgets | ~2 d |
| **P7** | Storage Phase 4 + Bus Tier 3 (optional) | Tier-3 swap-ins (Qdrant / Clickhouse); §24.10 RedisBus; checkpoints if revisited; named-schema registry if §24.3.6 trigger met | ~4 d |
| **Total** | (Tier 3 of §24.14 — C2/C5/C9/C3-advanced — deferred until consuming pack lands, adds ~14–18 d when triggered) (Original D-tasks #145–#155 superseded per §24.21.6) | | **~86–97 d** |

**Suggested ordering rationale:**

- **P1 first**: closes the CLI MVP cleanly, demos the platform
  end-to-end, low risk.
- **P2 next**: enables the community-pack story; independent of P3/P4.
- **P3 before P4**: workflow choice influences how `workflow_ref` in the
  `runs` table is populated. Doing storage on top of a settled workflow
  engine is cheaper than re-targeting later.
- **P4 → P5 → P6**: incremental; each phase keeps existing code working.
- **P7 optional**: pure power-user surface.
