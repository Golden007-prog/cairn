### 24.24 Decision: drop Restate from core — actions are mutating operations; durable HITL via LangGraph `interrupt()`, Temporal reserved for long-running

**Status: decided 2026-06-11. Implementation = backlog (Restate deletion +
durable-HITL build not started).** Supersedes the §3.4 "Restate preferred
(Apache 2.0)" line for the action executor.

#### 24.24.1 Why — licensing + design coupling

- **Licensing.** §3.4 calls Restate "Apache 2.0." That is wrong: the
  Restate **server is BSL 1.1** (Business Source License — source-available,
  not OSI-permissive; converts to Apache only on a release delay).
  **Temporal is MIT** (server + SDK), and it's the engine we already wired
  (§24.22, Temporal Step 3). A permissive (MIT/Apache) core must not take a
  hard dependency — even an HTTP-ingress one — on a BSL engine.
- **It's not a stub.** `core/actions/restate_handler.py` (266 LoC) is a
  real client that POSTs to a Restate ingress over `httpx`;
  `restate_service.py` (289 LoC) defines the `ActionSaga` workflow.
  Restate-the-engine isn't pip-installed (reached over HTTP), which is a
  *worse* smell: core hand-codes a client against a BSL engine's API.
- **Coupling.** The one capability Restate uniquely provides today is
  **durable HITL approval** (survive a crash while waiting on a human).
  `InProcessActionHandler` and `builtin/slack_approver.py` both punt
  slack-approve flows to `RestateActionHandler`. That coupling is the real
  thing to replace.

#### 24.24.2 The reframe — durability is the runtime seam, not an action-handler tier

Today two durability mechanisms compete: the action layer picks
`InProcessActionHandler` vs `RestateActionHandler` (handler tier) **and**
the engine has the runtime seam (`inprocess` vs `temporal`). That
duplication is the flaw.

The action saga — `dry_run → policy_gate → approval → execute → verify →
compensate` — is **already expressible in the locked §24.20.8 node
vocabulary**: `policy_gate`, `approval`, `operation`, `cleanup`. Therefore:

> A governed action is NOT a bespoke saga subsystem. It is a template
> fragment of **mutating operations** (`risk = "mutating"` + an executor),
> and its durability is whatever runtime the template runs on. **One
> durability mechanism, not two.**

This collapses the `ActionHandler` hierarchy into the operator + executor +
runtime model. The operator executor (`in_process` / `docker` /
`kubernetes_job` / `modal`) decides *where* a step runs — orthogonal to
*durability* (the runtime seam).

#### 24.24.3 LOCKED — two permissive durability tools, clear boundary

| Need | Tool | License | Why |
|---|---|---|---|
| Durable HITL approval + crash-resume for an **action saga** | **LangGraph checkpointer + `interrupt()` / `Command(resume=…)`** | MIT | Saga already compiles to a LangGraph graph; checkpointer (sqlite-vec / Postgres — `runtime-postgres` extra already declared) gives durable state; `interrupt()` is native durable HITL. No engine. This is the `verify-upstream` Check-A recommendation. |
| **Long-running / scheduled** durable workflows (GPU operations, nightly skills, cross-machine) | **Temporal** activities + signals + `RetryPolicy` | MIT | Already wired (§24.22). Survives deploys, supports scheduling. Reserved for work that genuinely outlives a process. |

**Do NOT** reintroduce a separate "action-handler durability tier." Durable
HITL = the `approval` node lowering to `interrupt()` (in-process /
checkpointer) or a Temporal signal (when already on the Temporal runtime).

#### 24.24.5 Sequencing note (why removing Restate now is safe)

Durable HITL via `interrupt()`/signal is **not built yet**; today it exists
*only* through Restate. But **Demo 2 explicitly cuts HITL** (§24.21.3) —
nothing on the live path waits on a human. So removing Restate now is safe:
in-process HITL (auto / CLI / Slack fire-and-forget) still works, and
**durable HITL is RM3 backlog**, not a regression on any shipping path.

#### 24.24.6 What this section closes

- Restate (BSL) is out of core — re-affirms the permissive-core principle
  and the §3.4 "one durable engine" intent, now corrected to **Temporal
  (MIT)** + the lighter LangGraph-checkpointer path for HITL.
- The action subsystem stops being a parallel durability tier and becomes
  template composition over mutating operations + the locked node types.
