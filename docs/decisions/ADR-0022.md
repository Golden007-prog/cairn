### 24.22 Decision: compiler AST strategy — LangGraph-shaped AST + JSON snapshots; no generic IR

**Status: decided 2026-06-11.** Evaluated a "generic IR → three backend
emitters (LangGraph / Temporal / Prefect)" proposal. Rejected the generic
IR; locked the existing single-AST architecture and added one new build
item (AST JSON snapshots).

**Locked:**
- The typed Pydantic AST (`TemplateSpec` + BT node models in
  `core/engine/schema.py`) **is** the compiler AST. One parser, one
  LangGraph lowering (`core/engine/compiler.py`). No string codegen
  anywhere (verified).
- **Temporal = durability wrapper, not a second compile target.** The
  existing scaffold (`core/runtime/temporal/`) runs the *same* compiled
  LangGraph graph via `temporalio.contrib.langgraph`
  (`TemplateWorkflow` + generic `run_node` activity, registry keyed on
  `(template_name, template_sha)`). Remaining: dep install + runtime
  switch wiring + smoke (~2–4 d, see "Temporal Step 3" above).
- **`agent_loop` is unsupported on Temporal** — submit-time validation
  gate fails loud; run in-process instead. Only `prompt` nodes and
  graph-in-activity are supported.
- **Dropped:** Prefect emitter (re-affirms §3.4), Rust compiler
  (endpoint §24.9 stays parked indefinitely), runtime-neutral
  `CompiledPlan` IR (endpoint §24.4 trigger discipline unchanged — and
  with Temporal handled by the plugin, no second runtime needs an IR).

**New work — AST JSON snapshot (~1.5–2 d):**

| # | Item | Detail |
|---|---|---|
| AST1 | Canonical AST serializer | JSON projection of the compiled AST; reuse the `compute_content_hash` canonical `model_dump` projection so hash and snapshot agree |
| AST2 | Golden AST tests | Fixture per shipped template pinning `template → AST JSON`; any grammar/lowering change becomes a reviewable diff. Prerequisite for safely fixing the subgraph_node propagation bug |
| AST3 | Run-record artifact | Persist the AST JSON alongside `template_hash` in run meta so replay/debug is self-contained |

  + subgraph propagation fix

#### 24.22.1 Clarification — the JSON AST is a *view*, not a lowering IR (harvested from `runtime-compiler.md`)

A recurring confusion ("don't we already have a JSON IR that becomes
LangGraph?"): **no.** `compiled.py::ast_json` (`spec.model_dump(mode="json")`,
byte-stable) is a **projection OUTPUT** of the typed `TemplateSpec`, used for
the content hash (§24.11.3), golden tests (AST2), and run-record persistence
(AST3, `runner.py`). The LangGraph build reads the **in-memory Pydantic AST
directly** (`compile_template` → `_build_state_machine(spec, …)`) and never
reads the JSON back. The model is **"AST is truth, JSON is a view,"** not
"JSON IR → lowered to N backends." The rejected `runtime-compiler.md`
proposal was the latter.

**Lowering map (the one real lowering, salvaged from `runtime-compiler.md`):**

| AST node | LangGraph |
|---|---|
| `agent` | node function |
| `agent_loop` | cycle |
| `operation` | node that calls the OperatorRunner |
| `condition` | conditional edge |
| `parallel` | fan-out/fan-in (`Send`) |
| `subgraph` | subgraph / expanded graph |

Invariant: LangGraph nodes call cairn services / the operator runner —
never a vendor SDK directly (re-affirms §3.3).
