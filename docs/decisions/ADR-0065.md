# ADR-0065 — Typed interrupt kind: a remote-job pause is not an approval gate

Status: Proposed (2026-07-07)
Relates to: #551 (seam 1 — the headline), #536; ADR-0038 (remote-job control loop);
ADR-0034 (HITL approval gate); the durable remote-job path
(`operator/runtime.py:_invoke_remote_job_durable`); the Temporal workflow
(`runtime/temporal/workflow.py`); the in-process dispatcher pause/resume
(`dispatch/dispatcher.py`).

## Context

cairn pauses a run via LangGraph `interrupt()` for two very different reasons:

1. **Approval** (ADR-0034) — a HITL gate; a human must approve/reject. Payload =
   an `ApprovalRequest` dict. Resume = the human's decision.
2. **Remote job** (ADR-0038) — the run submitted a long remote job and paused
   waiting for it; the control loop drives it and resumes with the job result.
   Payload = `{"remote_job": True, "run_id", "node"}` (`runtime.py:701`).

Neither runtime distinguishes them, so a **running remote job is mislabelled an
approval gate**:

- **in-process** (`dispatcher.py`): any paused run → `status="awaiting_approval"`
  + an `approval` event carrying the interrupt payload. A remote job shows up as
  "awaiting approval" with a `{"remote_job": true}` "ApprovalRequest".
- **Temporal** (`workflow.py:86-109`): every `__interrupt__` → the
  `cairn.surface_approval` activity + `wait_condition` on the `approve` signal. A
  remote job is surfaced as a pending approval and the console shows a bogus card.

The resume *plumbing* is already correct for both (the control loop calls
`resume_run`, which delivers the job result via the same `approve` signal / node
re-run). **This is a surfacing/status defect, not a resume defect.**

## Decision

Add a **typed interrupt kind** and branch surfacing on it. No change to the resume
mechanism.

- New `cairn/core/interrupts.py`: `KIND_APPROVAL = "approval"`,
  `KIND_REMOTE_JOB = "remote_job"`, and `interrupt_kind(value) -> str` — reads
  `value["kind"]`, falling back to `KIND_REMOTE_JOB` when a legacy payload has a
  truthy `remote_job`, else `KIND_APPROVAL`. Robust to dict / pydantic / None.
- Both interrupt sites stamp `kind`: the approval `ApprovalRequest`
  (`compiler.py:1273`) gets `kind="approval"`; the remote-job payload
  (`runtime.py:701`) gets `kind="remote_job"`.
- **in-process** (`dispatcher.py`, both the invoke and resume pause branches):
  a paused run whose interrupt kind is `remote_job` → `status="running"` (the work
  IS executing remotely; the control loop drives it) and NO `approval` event.
  Approval pauses are unchanged (`awaiting_approval` + the request payload).
- **Temporal** (`workflow.py`): branch on kind — `approval` → `surface_approval` +
  wait for `approve` (unchanged); `remote_job` → a `surface_remote_job` activity
  that records the run as running-remote (NOT awaiting-approval, NO ApprovalRequest),
  then wait for the completion signal (the same `approve` signal carrying the
  `JobStatus`) and resume.

### Explicitly NOT changing

- The resume path: `resume_run` still signals `approve` / re-runs the node; the
  remote-job node re-run still reads the store and returns. Unchanged.
- No new run status enum: a remote-job pause reuses `running` (honest — the remote
  job is running; the RemoteJobRecord already tracks it separately in the console).

## Consequences

- A remote job no longer masquerades as an approval under either runtime; the
  console shows it as running, and there's no phantom approval card to click.
- Small, contained: a discriminator + two branch points (in-process status, Temporal
  surfacing). The tested in-process path is fully unit-testable; the Temporal branch
  mirrors the existing approval branch.
- Backward-compatible: `interrupt_kind` infers the kind from the legacy
  `remote_job` key, so in-flight payloads without an explicit `kind` still resolve
  correctly.

## Build plan

1. `cairn/core/interrupts.py` — constants + `interrupt_kind` (+ unit test).
2. Stamp `kind` at both `interrupt()` sites (`runtime.py`, `compiler.py`).
3. `dispatcher.py` — status from `interrupt_kind` in both pause branches; suppress
   the `approval` event for remote-job pauses (+ dispatcher tests).
4. `workflow.py` + `activities.py` — branch surfacing; add `surface_remote_job`.
5. No-regression across the approval + remote-job control-loop tests.
