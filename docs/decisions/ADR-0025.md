### 24.25 Decision: roadmap scope prune (ahead of the docs restructure)

**Status: decided 2026-06-11.** A scope prune before splitting the docs by
lifecycle (vision / architecture / ADRs / living-roadmap) so dead weight is
not carried into the new structure. Two definitions:

- **DROP** = delete the section/phase and its references.
- **PARK (north-star)** = remove from the *active roadmap*; keep a one-line
  pointer in `vision.md` (or the named north-star doc) so the idea isn't lost.
- **KEEP** = stays in the forward roadmap.

##### ModelOps north-star (harvested from `modelops_pack_ideas_and_integrations.md`, now deleted)

If/when ModelOps packs are greenlit, **build order**: (1) Model Evaluation →
(2) Inference Optimization → (3) Fine-Tuning Readiness → (4) Fine-Tuning
Execution → (5) Full Training. Rationale: evaluation helps every team;
inference optimization is direct cost savings; readiness prevents bad
fine-tuning spend; execution only pays off after data+evals exist; full
training is powerful but expensive.

**MVP integration set:** Bifrost · MLflow · HF Datasets · HF PEFT/TRL ·
Unsloth · Langfuse-or-Helicone · Postgres · S3 · Presidio · Slack · GitHub.

**"Where does logic live" decision rule** (general, not ModelOps-specific):
reusable external system → integration MCP server; compute-heavy execution →
sandbox/K8s/training-job; small domain logic → optional pack-local code;
workflow/business logic → pack template; safety/budget/replay/approval →
core.
