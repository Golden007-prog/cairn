# ADR-0047 — Run provenance: versioned installed-workflows, a content-addressed schema store, and resolved-operator pinning

Status: Proposed (2026-06-29)
Relates to: ADR-0026 (locked architecture — declarative composition + the `invoke_operator` chokepoint), ADR-0020 (pack contract), ADR-0033 (credentials are references, never values), ADR-0046 (stateful infra capabilities), #109 (the `UIContract`), #76 (the run result backend — `result_payloads`), #214 (server-side install records), #218 (console IA). Tracked in #220.

## Context

Two gaps surfaced wiring the web console's "Run" surface:

1. **Runs aren't reproducible.** `dispatcher.run_template` persists `trigger.payload = {"template": ref}` only — no inputs, no resolved operators, no schema — and the template-run path computes the graph `output` then **discards** it (stores a near-empty `RunResultSummary`). You cannot answer "what inputs / which operators / what schema produced this run?" after the fact.
2. **Installed workflows are versioned and their schema drifts.** A reinstall can change a workflow's version *and* its input/output schema. A run must be pinned to the version + schema + operators it actually executed against, so upgrading a workflow later does not rewrite the meaning of an earlier run.

## Decision

Model run provenance with three stored entities; **the schema is data, referenced by hash, never a literal in code.**

### 1. Content-addressed schema store
`workflow_schemas` — one row per unique schema, keyed by `schema_hash` (hash of `input_schema + output_schema + step shape`); holds the `input_schema` / `output_schema` JSON-Schema docs. Derived from the pack template (data) and snapshotted by hash; every other record references the hash. Reuses the engine's content-addressing (`compiled.py`; the run `result_payloads` already carries `template_hash + template_ast`).

### 2. Versioned installed-workflow record (environment-agnostic)
One row per `(workflow_ref, version)`: `pack_ref/pack_version`, `schema_hash` (FK), `required_capabilities[]`, `composes` (operator refs + the operator **packs** that ship them), `config` (default environment/profile + tracker config + optional default inputs), `status` (`active | superseded`), actor + timestamps. Reinstall at a changed schema → new row + new `schema_hash`; the old row is `superseded`, never deleted.

### 3. Run-provenance fields (additive to `Run`)
`workflow_ref / workflow_version / schema_hash` + `environment/profile` (at create), `inputs` (validated values, at create — right before dispatch), `resolved_operators[]` (`{capability, operator, operator_version, risk, requires_approval}`, at run time), `outputs` (at completion — populate `result_payloads` on the template-run path).

### The capability vs. resolved-operator split
A workflow declares **capabilities**; the **environment binds** each → a concrete operator. So:
- the **installed-workflow record** holds `required_capabilities` + composed operator **packs** (env-agnostic, version-intrinsic);
- the **run record** holds the concrete `resolved_operators[]` (env-dependent, per-run).

This keeps the installed record stable across environments while every run stays reproducible:
```
Run = workflow_ref@version + schema_hash + environment + resolved_operators[] + inputs + outputs
```

## Consequences
- Every run is reproducible and drift-safe; upgrading a workflow leaves historical runs intact.
- Two new stores mirror the existing pattern (`triggers/store.py`, `registry_install.py`: InMemory + Sqlite, JSON `data` blob). Schema dedupes by hash.
- The web console becomes the 4th `UIContract` renderer (CLI/TUI/Slack already exist) — a hand-rolled JSON-Schema→form, no JSONForms dependency.
- **Security (ADR-0033):** secret-typed inputs are stored as *references*, never raw values, and redacted in the hash-chained audit. Non-secret config inputs persist directly.

## Out of scope
- JSONForms SPA (hand-rolled renderer keeps it dependency-free + hermetic).
- Operator version-solving on install (deferred, ADR-0045).
- Operator `requires_secrets` declaration (the marking that would render secret inputs as connection pickers) — tracked separately.
