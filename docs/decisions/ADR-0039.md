# ADR-0039 — The governed train→eval→promote spine: cost + quality gates, provenance, experiment sweep

Status: Proposed (2026-06-24)
Relates to: ADR-0034 (HITL), ADR-0038 (long-running job control loop / L1–L3), #125 (model-eval gate), #136 (experiment tracking), #126 (GPU-execution epic).

## Context

The ModelOps **operators** already exist: the dataset checks + `dataset/gate`, five
`train.run` providers (stub / modal / kaggle / runpod / vast), `model/gate`,
`model/register`, MLflow/W&B tracking (#136), and the #127 remote-job control
worker. What is missing is **governance glue, not operators**. Two fragilities
dominate, and both are *spend* fragilities:

1. **Paying for runs you shouldn't.** There is no cost ceiling before a GPU is
   provisioned, and no mid-training check that the model is actually learning —
   so money burns on over-budget or non-converging runs, discovered at the bill.
2. **Irreproducible, unprovenanced runs.** Nothing ties `dataset-hash → config →
   adapter → eval-verdict → who-approved` into one content-addressed record.
   W&B/MLflow track metrics but not fine-grained provenance/cost lineage.

**Design lens** (keeps this Cairn-shaped, not a me-too of W&B or a serving
framework): build only where the fix is **enforcing a guard at a chokepoint** —
a cost cap before spend, a quality abort during spend, a gate before promotion,
an audited provenance record. Benchmark design, autoscaling, dashboards, and
drift *detection* are **integrated, not built**. The enemy at every stage is
*silence*; Cairn's one job is to turn each silent waste into a loud, gated,
audited stop.

## Decision

Weave the existing operators into a **governed spine with four chokepoints + a
provenance record**, all cost-coupled.

### Gate 1 — Pre-flight COST gate (before provisioning)
- **`compute/quote`** — live cross-provider offers over the existing `compute.*`
  connections (Vast `/search/asks/`, RunPod GPU types, Modal/Kaggle) → ranked
  rentable options by price and fit.
- **`compute/estimate`** — VRAM + GPU-hours + $ from model × dataset × method
  (heuristics + the quote's pricing).
- **cost gate** — a deterministic verdict mirroring `dataset/gate`: estimate vs
  the `BudgetField` ceiling → pass / warn / fail, cited + audited → HITL approve
  if over budget.
- *Outcome: never spin up a GPU you can't afford or that won't fit the model.*

### Gate 2 — Mid-train QUALITY gate / early-abort (during training) — the L3 channel
- The in-container agent (in `cairn-train-gpu`) emits loss/eval metrics each eval
  step via `ctx.emit_heartbeat` (ADR-0038 L1).
- A **learning verdict** — is loss decreasing / eval improving vs thresholds?
  Reuse HF `EarlyStoppingCallback` for the in-loop signal + a cairn-side
  deterministic verdict.
- If **not learning**, the #127 control worker **aborts** the job (ADR-0038 L2
  cancel) and resumes the run as failed.
- *Outcome: stop paying the moment a run stops learning — "no point paying for a
  GPU if the model isn't learning." This is the cost+quality pairing.*

### Gate 3 — Post-train QUALITY gate (`model/gate`, #125 — exists)
Eval verdict (loss / overfit / judge, extensible to benchmark scores) before promote.

### Gate 4 — Promotion gate (`model/register`, HITL — exists)
Durable human approval; records who / what / when.

### Experiment sweep (different parameters, tracked + compared)
- Fan-out over N parameter configs — **reuse the existing Engine fan-out**
  (compiler/runner), NOT a new primitive.
- Each config is a governed run: cost-gated (Gate 1), learning-gated (Gate 2),
  tracked via #136 (MLflow/W&B), under one sweep-wide cost cap.
- A **compare/select** step picks the best by the `model/gate` verdict + the
  tracked metric; losers are recorded, not promoted.

### Provenance / lineage record (the glue)
Content-addressed `dataset-hash → TrainSpec/config → adapter → eval-verdict →
cost → promotion + approver`, written to the `audit/store` hash-chain. Reuses
`compiled.py` content-addressing — answers "what produced this model, what did it
cost, who approved it, can I replay it exactly."

## Levels (ADR-0038)
- **L1 observe** — heartbeat metrics onto the provenance record.
- **L2 abort** — the cost/learning kill (Gate 2).
- **L3 in-loop gate** — mid-train HITL/auto gate (the quality gate is its first consumer).

Transport: Temporal activity heartbeat (durable tier) / NATS (general), per ADR-0038.

## Reuse (verify-upstream)
- `dataset/gate` pattern → both new gates (cost, learning).
- `BudgetField` + `CostLedger` → the cost ceiling.
- #127 control worker → the mid-train abort.
- HF `EarlyStoppingCallback` → the in-loop learning signal (don't build early-stopping).
- Existing Engine **fan-out** → the sweep (don't build a fan-out primitive).
- #136 tracking → per-config experiment tracking.
- `compiled.py` + `audit/store` → the provenance record.

## Non-goals (integrate, don't build)
- Request-path serving / autoscaling (vLLM, KServe).
- Drift *detection* (Evidently, Arize) — but the governed retrain loop (drift
  signal → cost-capped, gated retrain → eval → promote) is an in-scope follow-up.
- Benchmark *design* / experiment dashboards (W&B, MLflow) — integrate; position
  as "governance, not tracking."

## Consequences
- New: `compute/quote`, `compute/estimate`, the cost gate, the learning verdict,
  the sweep compare/select; + the in-container agent + the provenance record.
- This **supersedes the standalone L3 design pass** — the mid-train quality gate
  *is* L3, given a concrete cost purpose.
- Every run becomes affordable (Gate 1), learning (Gate 2), good (Gate 3),
  approved (Gate 4), and reproducible (provenance). Each silent waste becomes a
  loud, gated, audited stop — the through-line that makes this a focused product
  rather than a pile of operators.
