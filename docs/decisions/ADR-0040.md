# ADR-0040 — The eval-delta gate + the produce/decide/enforce split (unlocking compression)

Status: Proposed (2026-06-25)
Relates to: ADR-0039 (the governed spine), #125 (`model/gate`), ADR-0031 (`eval.judge` / deepeval), #146 (lineage), #141 (spine epic). Children: #152 (eval-delta gate), #153 (`model/eval` lm-eval-harness wrapper).

## Context

`model/gate` (#125) is an **absolute** verdict: "is eval_loss below X, is the
overfit gap below Y" — a pure function of *one* model's own metrics. It cannot
express the question that dominates iteration and is the *entire* point of
compression:

> "Is this model **worse than the one we already have** — and if so, by more than
> we're willing to accept?"

That is a **relative** question: candidate vs. baseline, gated on the **delta**
against a **regression budget**. Compression — **quantize / distill / prune**
(and prompt-/route-optimize) — *intentionally* trades a little quality for large
wins in size, cost, and latency. The only governance question for every one of
them is identical: "did quality drop too much vs. the original?" So the whole
lane is one shape, and one gate unlocks it:

```
{baseline model} → {compress transform} → {candidate} → eval both → eval-delta gate → audit + lineage
```

Second, a recurring confusion worth pinning: **"eval" is two layers, not one.**
Conflating them invites reinventing an eval harness. The "don't reinvent the
wheel" rule applies to producing metrics, never to the verdict.

## Decision

Separate eval into **three layers**; build only the middle one.

| Layer | Does | Build or borrow |
|---|---|---|
| **1. Produce metrics** | run benchmark / judge / loss → numbers | **OSS — never reinvent** |
| **2. Decide** | numbers + thresholds → pass/warn/fail verdict | **cairn, ~50 lines — the product** |
| **3. Enforce** | verdict → HITL promote + hash-chained audit + lineage | already built |

### Layer 1 — producers (integrate, don't build)
- **Training loss / eval_loss** — free from the HF Trainer/TRL mid-training eval (already flows into `model/gate`).
- **LLM-as-judge quality** — **deepeval** (G-Eval), already wrapped as `eval.judge` (ADR-0031), routed through the cairn gateway.
- **Benchmark / task accuracy** (the gap) — a thin **`model/eval`** operator wrapping **lm-evaluation-harness** (EleutherAI; or HF `lighteval`), an optional `[eval]` extra, mirroring how `eval.judge` wraps deepeval. We do **not** write an eval/benchmark engine.
- **Model test-suites / drift** (optional) — deepchecks / Evidently / Giskard emit condition-based pass/fail and drift signals; ingest as a *signal*, never rebuild.

### Layer 2 — the eval-delta gate (the only genuinely new operator)
A deterministic operator mirroring `model/gate`: a pure function of
`{candidate_metrics, baseline_metrics, thresholds}` → cited pass/warn/fail.
- **Direction-aware deltas** — a small metric-direction map: *lower-is-better*
  (loss, latency, size, $) vs *higher-is-better* (accuracy, f1, judge_score), so
  "−0.008 accuracy" reads as a regression but "−73% size" reads as a win.
- **Regression budget** — thresholds become "acceptable regression" (e.g. ≤1%
  accuracy drop), not absolute bounds. It can **approve a quality drop** when it
  is within budget *and* the cost win is large — exactly the compression decision.
- **Baseline source** — the **model registry**: `model/register` already records
  `eval_scores` per version, so "the currently-promoted version's scores" is
  already on disk. No new store.
- **Complements `model/gate`** — absolute floor (`model/gate`) + relative budget
  (eval-delta) can both run; compression flows use the delta gate.

### Layer 3 — enforce (exists)
HITL promote (`model/register`) + `audit/store` hash-chain + the #146 lineage
record (the delta verdict becomes another link).

## Reuse (verify-upstream)
- `model/gate` structure → the delta gate (same shape: pure verdict + `audit_metadata`).
- `cairn/core/eval/comparison.py` — the **pattern** (`Baseline` save/load,
  `ComparisonReport`, `passes_threshold`). **Not a drop-in**: it is *case-level
  subset-match* for `cairn eval` regression testing, whereas the delta gate is
  *aggregate numeric* deltas — so mirror the pattern, add the metric-delta math.
- `model/register.eval_scores` → the baseline.
- `eval.judge` (deepeval) → already-wired judge producer; **lm-evaluation-harness**
  → the producer to wrap for benchmarks. No eval engine written.
- `audit/store` + #146 lineage → record the delta verdict.

## Pack placement (no fat packs)

Packs are distribution units grouped by **capability domain**, not "everything a
template touches" — `finetune.md` composing operators across packs is first-class
cross-pack composition (it already composes `dataset-readiness/check` and uses the
`audit/store` builtin). So:

- **The eval-delta gate (#152) and `model/eval` (#153) land in the eval pack, NOT
  the training pack.** Eval already *is* its own pack (`operator-eval-judge` /
  `eval.judge`); grow it (rename → `operator-eval`) to hold `eval.judge` +
  `eval.delta` + `model.eval` (+ `model.gate`, the existing quality verdict).
- `operator-training` keeps only `train.run` (the actual training). It has
  accreted cross-cutting operators (`cost/gate`, `model/gate`, `lineage/record`)
  — that fat-pack drift is tracked as a **separate refactor (#155)** (split into
  `train` / `eval` / `compute` / `model-registry` / `lineage`). New work must
  not deepen it.
- **`lineage/record` is its own official `operator-lineage` pack — NOT a builtin.**
  Only the *reader* (`cairn lineage`) is domain-neutral; the *record/writer* is
  model-shaped (`dataset → adapter → eval → cost → promotion`), so it's a domain
  pack. The generic substrate is `audit/store` (the builtin hash-chain) + the
  reader; another domain writes its own `lineage.record` rows via `audit/store`.

Target decomposition: `train.*` → training · `eval.*`/`model.gate`/`model.eval` →
eval · `compute.*`/`cost.gate` → compute · `model.register` → model-registry ·
`lineage.record` → its own `operator-lineage` (official).

## Non-goals (integrate, don't build)
- An eval / benchmark engine (use lm-eval-harness / deepeval / lighteval).
- Drift *detection* (Evidently, Arize) — the governed retrain loop is the in-scope follow-up, not the detector.
- A "model test suite" framework (deepchecks/Giskard) — ingest their result as a signal.

## Consequences
- **New:** one small operator (the eval-delta gate + schemas + `run-*` bindings)
  and one thin producer pack (`model/eval` over lm-eval-harness, optional extra).
  Both are "wire," not "build."
- **Unlocks the compression lane** — quantize / distill / prune become "wire a
  transform behind the existing delta gate," not "build N features." Each is the
  same governed `transform → eval-delta gate → audit/lineage` shape the spine
  already uses for data, cost, model, and learning.
- **Positioning:** W&B/MLflow *view* two runs; the delta gate *blocks* a promotion
  when the regression exceeds budget — track vs. govern, the same moat line.
