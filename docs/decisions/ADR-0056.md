# ADR-0056 — Licensing & open-source strategy

Status: **🟡 IN DISCUSSION — no decision yet** (2026-07-03). Do NOT apply a
license or go public until this is Accepted. The license pick is the owner's
call (and warrants a ~30-min lawyer sanity-check).
Relates to: the open-core-vs-SaaS deploy tiers (#408), the account/tenancy model
(ADR-0054, #392), the distribution epic (#209), and the pre-launch checklist issue.

## Context

cairn is currently a **private** repo. To go to market it needs an open-source
GTM (developers won't trust a black-box control plane that runs their pipelines
and holds their creds — inspectable + self-hostable is table stakes), **and** a
hosted SaaS so the "zero-ops" buyers can pay instead of running Postgres/Temporal
themselves. The question: which license protects the SaaS revenue without killing
adoption — decided **before** the repo goes public, because relicensing after
public + external contributors requires everyone's consent.

**Framing correction (vs the generic playbook):** for a pre-PMF governance/ModelOps
tool the real risk is **non-adoption, not theft**, and the "AWS native-services
your Apache code" threat is not near-term. So optimize the license for *adoption +
blocking the one threat that matters early* (someone reselling **your** hosted
SaaS), not against hyperscalers.

## Options on the table (undecided)

| Option | What | Protects SaaS? | Cost | Adoption friction |
|---|---|---|---|---|
| **A. Pure permissive** (MIT/Apache) | everything open | ❌ anyone can host + sell it | ~0 | lowest |
| **B. Fair-code / source-available** (BSL 1.1 · Elastic-2.0 · n8n Sustainable-Use) | whole repo public + self-hostable, but **only you may offer it as managed SaaS** | ✅ whole product | **~1 day** (LICENSE+NOTICE+headers+CLA) | low (self-host still free) |
| **C. Open-core `/ee`** | MIT/Apache core; "enterprise" features closed in `/ee` behind a license key | ✅ only the `/ee` features | **~1–2 wks + permanent overhead** (entitlement system, code seam, 2-edition CI, forever discipline) | low |

Within B: **BSL 1.1** auto-converts to Apache after ~3 years (good "eventually
open" optics); **Elastic-2.0 / n8n Sustainable-Use** are simpler with no
time-conversion.

## Recommendation (proposed, not decided)

1. **Adopt fair-code (lean BSL 1.1) on the whole repo now.** ~90% of the
   protection for ~5% of the effort; keeps everything inspectable + contributable.
2. **Add a CLA/DCO** before external contributors (preserves the option to
   relicense later).
3. **Defer the `/ee` split** until (a) enterprise customers explicitly ask for
   SSO/RBAC/audit-retention and (b) there's headcount to maintain two trees. Build
   the multi-tenant/SSO/RBAC pieces **EE-native behind an `is_licensed(feature)`
   seam when built** — ADR-0054's Account/membership/roles model already provides
   that seam, so no repo split or migration is needed to start monetizing later.
4. **Never gate the governance core** (policy · gates · HITL · the audit trail ·
   packs). It's the differentiator *and* the trust-builder; open governance is
   *why* people trust the control plane.

**Natural future `/ee` (paid) surface** (when C happens): SSO/SAML, advanced RBAC,
multi-tenant control plane (ADR-0054), audit-log retention + export, hosted
secrets governance, the internal-SaaS observability tier (already tier-split #408).

## Open decision (owner)

Pick one before going public: **B-BSL** · **B-Elastic-2.0/Sustainable-Use** · **C-open-core**.
Everything downstream (LICENSE file, CLA bot, headers, the pre-launch checklist)
is blocked on this pick. No code/license changes until this ADR is Accepted.

## Alternatives / notes
- Pure permissive (A) rejected as the *primary* license — leaves SaaS undefended.
- This is a business + legal decision, not purely engineering; a lawyer should
  confirm the final license text + CLA before it's applied.
