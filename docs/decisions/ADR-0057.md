# ADR-0057 — Packs ship runnable + evaluatable payloads (tiered demo/sample data, golden data, seed config, result evaluation)

Status: Proposed (owner-designed 2026-07-04; ADR-first before build — epic #442)
Relates to: the distribution epic #209 / ADR-0045 and the registry catalog
(`cairn-registry/index/catalog.json`, `build_catalog.py`), server-side install
ADR-0055 / #211, the pack contract (`DemoSpec`, `[assets].evals` in
`cairn/core/pack/manifest.py`), the core eval layer (`cairn/core/eval/` —
`score_case`, baselines), the eval operators (`eval/judge`, `eval/benchmark`,
`model/eval`, `rag/eval`), the inline gates (`model/gate`, `cost/gate`), the
pilot scorecard + `pilot_scores` store, model-roles #352, the connector catalog
#434, and the Langfuse trace push (#242 P3) + deep-link (#439/#435).

## Context

A pack today = **operators + workflow templates + a thin `[demo]` prefill**. PR
#439 enriched the engine-bundled `[demo.*]` blocks, but that only helps packs
that live in the engine. The owner wants a pack to be a **self-contained,
runnable, and evaluatable unit** that travels through the registry: it should
ship the **sample data it was tested against** (3 tiers), its **golden/eval
data**, its **config seed**, and a declaration of **how its results are
evaluated** — plus let a user **evaluate a produced artifact on demand**. And the
format must be **generic** (work for any future pack), while packs stay **DATA,
never code**.

Most primitives already exist (`DemoSpec` with `tier` + `eval_path`,
`[assets].evals`, `score_case`, `field_map`, the four eval operators,
`model/gate`, the pilot scorecard). This ADR fixes the *model* so the remaining
work is wiring + one new capability, not a rebuild.

## Decision

**D1 — Four payloads, one bytes-rule.** A runnable+evaluatable pack carries four
payloads with different size/lifecycle: **seed config** and **eval recipe** are
tiny and live **inline** in `pack.toml`; **sample data** (3 tiers) and
**golden/eval data** follow the rule *small representative data ships in the
wheel (`examples/`, `evals/`); large data is always a reference (HF Hub id / URL
/ benchmark name) resolved at run time.* (Already the de-facto pattern in
`dataset_readiness`.)

**D2 — Eval method is an operator capability, not a manifest enum.** There is an
`eval` capability; `subset` / `judge` / `benchmark` / `rag` / `langfuse` are
operators that **provide** it. A recipe references one and it resolves through
`composes`, is governed, model-bound, and schema-validated by the **same
machinery that runs workflow operators**. A new eval method = a new operator
pack; the engine and manifest schema never change. The console derives
cost/offline/GPU warnings from operator metadata that already exists
(`non_deterministic`, `gpu`, `risk`, `supports_mock`).

**D3 — The recipe is the seed's shape, wired to the run's output.**
`[demo.*].inputs` seeds the *workflow's* schema; `[demo.*].eval.inputs` seeds the
*eval operator's* schema, with a `$output.*` selector binding the run's result
in. `uses = "eval/subset"` names the operator — no method vocabulary, no bespoke
dispatcher.

**D4 — Two evals answer two questions.** **Test eval** (`[demo.*].eval`, attached
to a demo *tier*): golden, deterministic (`eval/subset`), runs in CI +
`cairn eval` — proves the pack still behaves as tested. **Runtime eval**
(`[eval.*]`, attached to the *workflow*): reference-free, runs on real runs.
**Golden-set comparison does not apply to real runs** — no expected output can
exist for unseen data. Runtime eval by output shape: `model/gate` on the output's
own metrics (structured signal) · `eval/judge` (open-ended text) · `eval/benchmark`
(model artifacts) · `compare_to_baseline` (drift) · human sampling (backstop).

**D5 — Golden provenance is governed.** Distinguish **snapshot golden**
(record-then-review; guards drift) from **authoritative golden** (human/curated
label; guards correctness) — never conflate them. Determination: deterministic
packs use record-and-review (snapshot, like `--updateSnapshot`); true-label tasks
use human/curated labels (LLM may bootstrap, human spot-checks; the judge never
generates the golden it then judges). Ownership: **pack author** for the shipped
test tier, **deploying team** for their own data, **nobody** for real runs.
Golden files are **versioned + attributed + method-tagged**, and a golden change
is a **reviewed** act (diff in the pack PR) — never auto-regenerated, because it
redefines "correct."

**D6 — Per-run policy: not everything runs on every run.** Cheap **deterministic
gates** (`model/gate`, `cost/gate`) run on **every run, inline** — they are
governance/control-flow, not quality scoring. The **LLM judge is sampled**
(`PilotScore.sampled_pct` exists), run **async, off the hot path**. **Benchmarks
are per model-artifact, never per inference-run.** **Human review is a small
slice.** Scoring is therefore a **decoupled post-step over a run's stored output +
trace** (so a fraction can be scored off the hot path and history can be
re-scored); gates stay inline because they must block.

**D7 — Optional user-initiated eval on produced artifacts.** A user can choose to
evaluate any completed run/artifact on demand ("Evaluate this result"), running
the runtime recipe (or a picked eval operator) over the already-produced output —
no re-run, works on historical runs. Enabled by D6's decoupled-post-step model.

**D8 — Langfuse: governed-score sink + optional `eval/langfuse` compute.**
Langfuse has a real eval stack (Scores API; managed LLM-as-a-judge on traces /
dataset experiments; in-UI code evaluators; annotation queues; score analytics),
so it is not merely a viewer. Its roles here: (1) **default governed score sink** —
cairn computes via its own operators (governance preserved) and **pushes scores
to the Langfuse Scores API** so they show on the trace; (2) **human annotation +
analytics surface** (annotation queues back D6's human backstop; analytics
overlaps `PilotScorecard.inter_rater`); (3) an optional **`eval/langfuse`
operator** — a new provider of the `eval` capability that pushes
`{input, output, trace}` to Langfuse and runs the eval **there** (managed judge /
experiment), reading the score back. Because that judge runs on Langfuse infra it
**bypasses cairn's gateway and egresses data**, so `eval/langfuse` is **opt-in,
connection-gated, and flagged as ungoverned**. Net: **two judge paths by design**
— `eval/judge` (governed, in-cairn, default) and `eval/langfuse` (delegated,
ungoverned, opt-in).

**Guardrail — packs stay DATA.** The recipe is **declarative-only** (operator ref
+ input bindings + pointers). Any custom scoring MUST be a real operator, never an
inline snippet/lambda/expression in `pack.toml`. This sharpens the boundary: **the
pack declares what good looks like; an operator computes whether the result is
good.**

## Manifest shape

```toml
[[demo.check]]                      # a demo TIER
tier = "easy"; offline = true; approx_rows = 20
  [demo.check.inputs]              # seeds the WORKFLOW schema (#3 seed)
  path = "examples/sample.jsonl"
  [demo.check.eval]               # TEST eval — golden, deterministic, CI (D4)
  uses = "eval/subset"            # an operator ref (D2), not an enum
    [demo.check.eval.inputs]      # seeds the EVAL OPERATOR schema (D3)
    actual = "$output.report"; expected = "evals/check.easy.jsonl"; threshold = 0.8

[eval.check]                        # RUNTIME eval — reference-free, real runs (D4)
uses = "model/gate"
  [eval.check.inputs]
  metric = "$output.report.readiness_score"; at_least = 0.80
```

## Consequences

- A registry-installed pack surfaces the identical "Try + evaluate" loop as an
  engine-bundled one; the wheel stays small (large data is by-reference), the
  catalog carries the metadata.
- Adding an eval method is "ship an operator pack" — the engine, schema, and
  console are untouched (D2). `eval/langfuse` is the first proof of this.
- One artifact serves three consumers: the easy-tier sample + golden set is the
  demo prefill, the CI golden-fixture test, and the `cairn eval` regression set.
- Governance is preserved by default (compute in-cairn, sink to Langfuse); the
  ungoverned Langfuse compute path is explicit, gated, and flagged, not implicit.
- Cost is proportionate: gates every run (free), judge sampled, benchmark
  per-artifact — no universal LLM-judging.

## Alternatives considered

- **Closed `method = subset|judge|benchmark` enum in the manifest** — rejected;
  it re-encodes operators as a schema enum, drifts from reality, and forces an
  engine change per method. D2 (capability) supersedes it.
- **Golden comparison for real runs** — rejected as impossible (no expected output
  for unseen data); real runs use reference-free eval (D4).
- **Eval as a node baked into the workflow graph** — rejected; a decoupled
  post-step lets us sample, run on-demand (D7), and re-score history (D6). Gates
  stay inline because they block.
- **Langfuse as the default/governed eval compute** — rejected; its managed judge
  runs off-gateway and egresses data. Langfuse is the score sink + an opt-in
  ungoverned compute operator, never the governed default (D8).
- **Recipe / eval config living in the bundle** — rejected; the recipe is
  intrinsic to the workflow (what "good" means doesn't change with composition),
  so it lives in the pack; the eval *operator* resolves through the same
  composition path as workflow operators.
- **Inline scoring snippets in `pack.toml`** — rejected (guardrail); custom
  scoring is a real operator.

## Implementation status

- **Phase 1 (distribution)** — the registry catalog carries per-workflow demo
  tiers (`cairn-registry` `build_catalog._demos` → `catalog.json`); FE Library
  pre-install render is the remaining slice.
- **Phase 2 (eval capability + recipe runner)** — **DONE** (branch
  `442-phase2-eval-recipe`). Delivered:
  - `eval` capability via a new builtin operator **`eval/subset`**
    (`eval.subset`) in the eval pack — deterministic structural scorer wrapping
    `cairn.core.eval.score_case` (D2).
  - Manifest recipe schema: `[demo.*].eval` (TEST) + `[eval.*]` (RUNTIME),
    parsed into `manifest.EvalRecipe` (`uses` + `inputs`), guardrail-checked
    declarative-only.
  - The **`$output.*` selector** + scoring-pass dispatcher
    `cairn.core.eval.run_eval_recipe` — resolves a run's stored output into the
    eval operator's inputs, invokes it through the ordinary registry surface,
    normalizes a `passed`/`verdict`. A decoupled post-step (D6/D7); never
    re-runs the workflow. The `$output` scope is recipe-local — the engine's
    §24.20.6 binding grammar is untouched.
  - `dataset_readiness` ships the recipe + snapshot golden (`evals/`), and
    `cairn eval <pack> --recipe [--tier|--runtime] --output <run-output.json>`
    scores a produced artifact (D7). Acceptance met: scores the easy tier vs its
    golden set (pass) and fails on a seeded regression.
- **Phase 3 (console loop) — DONE.** `POST /runs/{run_id}/evaluate` (D7
  "Evaluate this result") scores a completed run's **stored output** with the
  workflow's declared recipe — runtime `[eval.*]` by default, a demo tier's
  test recipe when `{"tier": …}` is sent; 404 (no output) / 422 (no recipe)
  are actionable. Reuses `run_eval_recipe` via `extract_run_output` +
  `resolve_runtime_recipe`/`resolve_test_recipe`. Console: an "Evaluate this
  result" button on the run report (`EvaluateResultButton`) renders the
  verdict + mismatches, and flags the ungoverned path when `governed=false`.
- **D8 (`eval/langfuse`) — DONE (operator).** A new provider of the `eval`
  capability that pushes `{input, output, trace}` to Langfuse and reads a
  managed score back; opt-in, connection-gated, self-flags `governed=false`
  (the delegated, ungoverned judge path). The in-cairn governed default stays
  `eval/judge`. Not yet wired: the automatic score-**sink** (push every
  cairn-computed score to the Langfuse Scores API) — additive follow-up.
- **Phase 1 tail — DONE (render).** The Library detail modal + card show a pack's
  demo tiers pre-install from `catalog.json.demos` (already passed through by
  `/registry/catalog`). Live data awaits the registry catalog carrying `demos`
  (registry PR #1 merge + mirror re-sync — owner/registry side).
- **RUNTIME recipe shipped on `training/finetune`** — `[eval.finetune]` uses
  `model/gate` over `$output.metrics`, so a completed fine-tune can be
  re-verdicted on demand (deterministic, no GPU). This is the RUNTIME-plane
  proof on a real workflow and **reconciles #396** (per-run eval): the engine
  scorecard + `model/gate` operator + the recipe supersede the proposed
  standalone `eval.yaml`; environment overrides of the thresholds remain open.
  - Remaining follow-ups: the D8 score-sink (auto-push scores to the Langfuse
    Scores API); persisting D7 results into the pilot report; environment
    overrides of runtime-eval thresholds (#396 residual).
