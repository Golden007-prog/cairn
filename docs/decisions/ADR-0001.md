### 24.1 What shipped this session (foundation complete)

The CLI surface — the original MVP-six minus eval — is in place. Engine
stays domain-neutral; CLI is the thin shell.

```
cairn/cli/
├── main.py
├── commands/
│   ├── doctor.py         # preflight (formerly cairn/core/doctor — moved)
│   ├── ls.py             # walks pack registry; renders contributions
│   ├── validate.py       # offline artifact validation (CLI half of core/validate.py)
│   ├── run.py            # fire one trigger; persist replayable trace
│   ├── replay.py         # render past run's JSONL trace
│   └── init.py           # sub-app: pack/template/skill/policy scaffolding
└── runs/
    ├── paths.py          # .cairn/runs/<run_id>/ layout
    ├── writer.py         # JSONL JsonlEventSink (EventSink-shape)
    └── reader.py         # parser for replay
```

Key architectural calls baked in here:

- **`CheckResult` and the `Status` literal moved to `cairn.core.pack.protocol`.**
  Packs produce CheckResults via `doctor_checks`; they cannot import from
  `cli/`. The doctor orchestrator (`run_checks`, `format_report`) lives in
  CLI; the data type is part of the pack contract.

- **CLI traces use JSONL, not SQLite.** The production dispatcher path
  (`SqliteInvestigationStore`) stays untouched. CLI's `JsonlEventSink`
  satisfies the same `EventSink = Callable[[str, dict], Awaitable[None]]`
  shape from `cairn.core.engine.runner`. Two parallel sinks, same
  contract. (See §24.4 for the upcoming unification.)

- **Pack scaffolding uses a flat layout.** A pack is *one directory* that
  is simultaneously project root (holds `pyproject.toml`), the importable
  Python package, and the pack root (holds `pack.toml`). Setuptools knows
  this via `package-dir = {"<name>" = "."}` plus an explicit
  `packages = ["<name>", "<name>.code"]`. This mirrors the in-tree
  incident pack layout — one mental model across in-tree and community
  packs, no `project/project/` duplication. (User preference; see MEMORY
  note on rejecting `src/`-style nesting.)

- **Generated artifacts are runnable, not empty.** Every `init` output
  passes `cairn validate` immediately and `cairn ls` discovers
  the pack after `pip install -e .`. The user never debugs missing
  required fields before writing their own logic.

- **Entry-point form**: `<name> = "<name>.code:pack"`. The `:pack` suffix
  points at the `Pack` instance attribute; without it the loader resolves
  to a module and skips.
