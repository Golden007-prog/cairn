# ADR-0059 — Closed-loop telemetry storage: Postgres ledger + OTLP/OpenInference fan-out + console verdict UI

Status: Proposed (2026-07-05, for the failure-driven eval epic #480)
Relates to: ADR-0049 (DB system-of-record), ADR-0050 (migration runner
`cairn/core/storage/migrations.py`), ADR-0058 (storage unification / `OBS_STORAGE`),
ADR-0047 (run provenance), ADR-0012 (governed self-improvement), epic **#480** and its tickets
(#474 taxonomy · #475 metric contract · #476 capture · #477 Bus Tier 2 + continuous eval · #478
suggestion engine · #479 pairwise) · pre-existing #244 (eval ledger) · #472 (explainability view).

## Context

The closed loop (`run → evaluate → type the failure → cluster → suggest → human-gated PR`) needs a
home for logs, traces, LLM spans, tool usage, eval verdicts, failure labels, and cost. The open
question was **"one central ledger for everything?"** A naive reading — *store everything in
Postgres, then export to ClickStack over OTLP, then Langfuse for UI* — is a **linear pipeline and
is wrong**: it would funnel millions of raw spans through the transactional system of record (the
exact thing tiering exists to avoid) and misroutes the trace UI as a downstream of the warehouse.

What already exists (do not rebuild — ADR-0058 / Check D):
- **Postgres run+event store** (system of record, ADR-0049; `core/storage/`), **migration runner**
  (ADR-0050, no ORM), pilot_scores, workflow_registry.
- **OTLP export pipe** for spans + metrics (`core/obs/telemetry.py`, `core/obs/metrics.py`,
  `OTEL_EXPORTER_OTLP_ENDPOINT`); events.jsonl sink (`core/obs/events.py`).
- **ClickHouse already named the Tier-3 events swap-in** (`core/storage/protocols.py:14,22`);
  ClickStack backend wired. **Langfuse** wired (+ `eval/langfuse`).
- **Eval ledger: ABSENT** (this is #244, delivered here as schema).

## Decision

### D1 — Topology is a FAN-OUT from the run, not a pipeline through Postgres

```
                    ┌──→  POSTGRES  (system of record)     ← direct, synchronous, the truth
                    │      runs · events · eval verdicts · failure labels · cost · suggestions
   cairn run ───────┤
                    └──→  OTLP emit (spans, OpenInference-shaped)   ← raw, high-volume, skips PG
                           │
                           ▼
                    OTel collector ──┬──→  CLICKSTACK   (analytics: p95, cost-by-wf, clustering)
                                     └──→  LANGFUSE     (trace-debugging UI for humans)
```

The engine writes structured rows **straight to Postgres** *and* emits spans **straight out over
OTLP** — two independent write paths from the same execution. **Raw spans never transit Postgres.**
The collector fans spans to ClickStack (analytics) and Langfuse (UI); Langfuse is **not** downstream
of ClickStack. All tiers are joined by **`run_id`**.

### D2 — The dividing line: gate/audit → Postgres; aggregate-at-volume → ClickHouse

| Data | Store | Why |
|---|---|---|
| runs, events, **eval verdicts, failure labels, cost, suggestions** | **Postgres** | bounded; you GATE / AUDIT / JOIN on it — it must be the transactional truth |
| raw spans, tool-call detail, per-token metrics | **ClickHouse (ClickStack)** | unbounded; you AGGREGATE over it (p95, cost-by-workflow, failure-rate-by-model, clustering) |
| trace-debugging waterfall | **Langfuse** | human span exploration; already ClickHouse-backed |
| distilled lessons | **episodic memory** | NEVER the eval DB (ADR-0012 principle) |

Rule of thumb: **if you gate or audit on it, Postgres; if you aggregate over it at volume,
ClickHouse.** Postgres holds the *system-of-record subset* — not raw spans, not per-token detail.

### D3 — Schema delta (via the migration runner, no ORM)

Extend what exists; **steps are the existing event stream** (runs+events are coupled by design,
`protocols.py:8`) and **raw spans already live in ClickHouse** — so no `workflow_steps` table. Add
the verdict/label layer:

```sql
-- extend existing `runs`
runs  += failure_type JSON        -- ["TOOL_FAILURE", ...]      (#474)
      += cost_baseline_usd NUMERIC -- counterfactual (Slice F)
      += final_verdict TEXT        -- pass | fail | degraded

-- NEW: eval ledger (#244)
eval_runs(         eval_run_id PK, run_id FK, recipe, tier, verdict,
                   aggregate_score, judge_meta JSON, created_at )
eval_case_results( case_result_id PK, eval_run_id FK, case_id, slice JSON,
                   passed, score, expected_ref, actual_ref )

-- NEW: failure labels (#474) — the diagnosis primitive
failure_labels(    label_id PK, run_id FK, failure_type, classifier,   -- deterministic | llm
                   evidence JSON, created_at )                          -- refs to events/spans

-- LATER (#478): suggestions — schema already in ADR-0012 §24.12
```

Volume analytics (p95, cost-by-workflow, cluster counts) run against **ClickHouse over the spans**,
joined to these Postgres rows by `run_id`. Row store = verdict truth; column store = aggregation.

### D4 — Egress: standards-shaped, not per-vendor integrations

| Out to… | Mechanism | Status |
|---|---|---|
| Any OTLP backend (Datadog, Grafana Tempo/Mimir, Honeycomb, ClickStack) | OTLP export | ✅ wired |
| Phoenix / Arize / OpenInference consumers | **OpenInference** span attributes on the same spans | +#476 |
| Eval scores shown on traces | Langfuse **Scores API** via `eval/langfuse` | 🟡 operator exists; score-*sink* to wire |
| Slack / webhooks / downstream | notification bus (outbound-only) + cascade webhook | ✅ exists |
| External system's traces **into** cairn | **out of scope** — on-platform only (#480 scope decision) | by design |

Because emit is OTLP + OpenInference, cairn connects to virtually any observability/SIEM/warehouse
**without per-vendor code** — point the collector at them.

### D5 — Console UI: cairn owns the VERDICT layer; Langfuse owns the raw trace

The console must let you *point and answer the three questions* (diagnose failures / prove cost /
show transparency) on cairn's own runs. It does **not** rebuild a span waterfall — that exists in
Langfuse; cairn **deep-links out** to it. Same own-the-verdict / bind-the-viewer split as the rest
of the platform. New surfaces in `cairn/web/src/views/` (routed in `routes.tsx`):

- **Per-run "Why?" drill-down** (the explainability view, #472 part 1) — for one run:
  Evidence · Tools used · Policies evaluated · Citations · Cost · **failure labels** · eval verdict,
  assembled from Postgres (ADR-0047 provenance + the new tables). A **"Open trace in Langfuse"**
  deep-link handles raw span debugging. *Reused verbatim by the compliance demo later.*
- **Insights dashboard** (new) — across runs, backed by ClickHouse aggregations + Postgres labels:
  - *Diagnose:* failures grouped by `failure_type` (+ clusters once #478 lands).
  - *Cost:* cost per workflow vs `cost_baseline_usd`, with the delta — the "reduces cost, provably"
    answer.
  - *Health:* success/failure rate, p95 latency, tool-failure rate.
- Extends the existing **Runs / Audit** surfaces; no new trace-viewer.

The bar this UI must clear: *sit in front of it and answer "can we diagnose failures, prove cost
reduction, and show full transparency?" by pointing at the screen.*

### D6 — Eval computes IN cairn (system of record); Langfuse is a sink; executors are pluggable

The **verdict is governed and reproducible, so cairn computes and owns it** — never a third party.
- **Compute:** the declarative recipe (`[eval.*]`, ADR-0057) runs cairn's **eval operators** inside
  the governed pipeline (cost-tracked, policy-gated, provenance-recorded, `cairn.lock`-pinned).
- **Store:** verdict + score + failure labels + judge metadata → the **eval ledger (Postgres)** =
  system of record. The human "clean report" is a **projection rendered from the ledger** (per-run
  "Why?" #481, exportable as an immutable audit artifact) — not a separately-maintained blob.
- **Langfuse = read-only sink:** the verdict is **pushed** to the Langfuse Scores API so it shows on
  the trace for human browsing. Langfuse **never computes the authoritative verdict.** (The existing
  `eval/langfuse` operator delegates a judge to Langfuse but is `governed=false` — an opt-in
  ungoverned escape hatch, not the default.)
- **Executors are not one framework — they're pluggable governed operators**, each wrapping a
  best-in-class library as an optional extra with a deterministic fallback: **deepeval** (`eval/judge`,
  the runtime-judge **default**) · **ragas** (`rag/eval`) · **lm-eval/lighteval** (`eval/benchmark`) ·
  **deterministic gates** (schema/cost/PII/citations — run first, free) · **eval/pairwise** (#479).
  The recipe seam is the anti-lock-in hedge: adding a method later is a new operator, not a migration.
  Order at runtime: **deterministic gates first (free) → LLM-judge only for the quality tail.**

## Consequences

- **Preserved:** one transactional system of record; replayability; provenance/audit; no span-volume
  pressure on Postgres; standards-based egress; the ADR-0012 line (UI shows diagnosis; actuation
  stays human-gated).
- **Cost:** the schema delta (3 tables + 3 columns via the migration runner), the continuous-eval
  writer (#477), OpenInference attrs (#476), and the two console surfaces.
- **The win:** what looked like "design a data platform" is a **schema extension + one consumer +
  UI** on the platform that already exists — not a new storage system.

## Non-goals

- A single mega-table / "everything in Postgres" (D1/D2 reject it).
- A cairn-built span waterfall / trace explorer (deep-link to Langfuse).
- Ingesting external systems' telemetry into cairn (on-platform scope, #480).
- A new analytical engine (ClickHouse via ClickStack is the tier).
