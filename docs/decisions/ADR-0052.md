# ADR-0052 — Environment backends configurator + capability provisioning

Status: Proposed (2026-07-01)
Tracking: epic #301 (sub-issues #302–#312).
Implements: ADR-0046 (stateful infra capabilities as enable-a-backend — the *principle* this ADR makes concrete).
Relates to: ADR-0023 (profile-owned RAG build config), ADR-0033 (credentials are references, never values), ADR-0037 (OAuth broker seam), ADR-0042 (operator granularity — one verb per operator, no new kinds), ADR-0043 (remote/exec + NATS worker channel), ADR-0026 (three-layer pack/profile/env), the #109 UIContract (schema-driven forms), #68/#70 (two-axis connections), #39 (move RAG ingest/query into an operator pack), #77 (RAG retrieval-quality eval), #170 (LangGraph Store — considered, not adopted), #178 (live remote-compute e2e), #196/#197 (trigger catalog).

## Context

A verification sweep (2026-07-01) confirmed a consistent shape across the runtime's stateful/optional capabilities: **the backend impls exist and work, but the user-facing control surface does not, and configuration is scattered across environment variables.** Concretely:

- **RAG** — core LlamaIndex ingestion pipeline (`cairn/services/rag/`), backends `sqlite_vec`/`pgvector`/`qdrant`/`pinecone` selected by `RAG_VECTOR_STORE`; autoindex gated by `OBS_RAG_AUTOINDEX`. Only the incident pack consumes it (declares `[requires.rag.*]`).
- **Memory** — episodic store (`cairn/services/memory/store.py`) + `memory_local` operator; **hard-wired ON** (`memory_enabled=True`), auto-writes every run, opt-out only by editing skill YAML. No enable/backend UI.
- **Storage / runtime / bus / trigger inbox / job channel / remote exec** — each selected by its own env var (`OBS_STORAGE`, `OBS_BUS`, `OBS_TRIGGER_INBOX`, `OBS_JOB_CHANNEL`, `OBS_REMOTE_JOB_DURABLE`, profile `durable_runtime`), none surfaced in the console.

ADR-0046 already decided the *model* (packs declare an abstract need; the environment enables a backend; the console surfaces but does not own it). This ADR makes it concrete: **one self-describing profile schema, one schema-driven form, credentials bound from the connection catalog, and doctor validation of pack needs against what the environment provisions.**

## Decision

### 1. The profile is the single source of truth; backends are a self-describing schema

Promote the scattered env vars into a structured `backends` section on the profile (extending `ProfileRecord.backends`, today `{llm_gateway, embedder, durable_runtime}`). The profile TOML/record stays authoritative; env vars remain a fallback/override for headless deploys. Each configurable capability is one field carrying **control-type metadata**:

- `type: boolean` → rendered as a **checkbox** (enable/disable: memory, RAG autoindex, remote execution, durable inbox).
- `enum` + `default` → rendered as a **dropdown** with the default pre-selected (backend choosers).
- open-valued (DSN, host, URL, path) → a **text input**, typically revealed only when a backend that needs it is selected.
- every field carries a one-line `description` → rendered as **help text** beside/under the control.

The canonical capability inventory (the fields the configurator manages):

| Capability | Control | Default | Choices | Legacy env |
|---|---|---|---|---|
| Run/event storage | dropdown (+DSN text) | `sqlite` | sqlite · postgres | `OBS_STORAGE` |
| RAG vector store | dropdown (+conn) | `sqlite_vec` | sqlite_vec · pgvector · qdrant · pinecone | `RAG_VECTOR_STORE` |
| RAG autoindex | checkbox | off | on/off | `OBS_RAG_AUTOINDEX` |
| RAG doc parser | dropdown | `default` | default · docling (PDF) · markitdown (office) | — (new operator) |
| Embedder | dropdown | `fastembed` | fastembed · google-genai · openai | profile `embedder` |
| Memory | checkbox + dropdown | off | enable + backend + auto-capture | (shares `RAG_VECTOR_STORE`) |
| Event bus | dropdown | `inprocess` | inprocess · (postgres/redis future) | `OBS_BUS` |
| Trigger inbox | dropdown + checkbox | `sqlite` | sqlite · postgres · nats; durable on/off | `OBS_TRIGGER_INBOX` |
| Remote job channel | dropdown | `inmemory` | inmemory · nats | `OBS_JOB_CHANNEL` |
| Remote execution | checkbox + dropdown | off | ssh · docker · kube · ray | `OBS_REMOTE_JOB_DURABLE` |
| Durable runtime | dropdown | `in_process` | in_process · temporal · dbos | profile `durable_runtime` |
| LLM gateway | dropdown (+conn) | — | per configured gateway | profile `llm_gateway` |

### 2. One schema-driven form (do not hand-roll)

The Environment backends form is generated from that schema by the **existing UIContract renderer (#109)** — the same JSON-Schema→form path used by the run form. `boolean→checkbox`, `enum+default→dropdown`, `string→text`, `description→help text`. It writes back to the profile via the existing structured endpoint (`GET/PUT /ui/api/profiles/{name}/form`), extended to emit the control-type + description + default metadata. Lives in `EnvironmentsView`. **No new form framework** (no JSONForms) — consistent with the run form and the trigger form (§6).

### 3. Backend credentials are bound from the connection catalog, never raw env

A backend that needs credentials (Qdrant, Postgres, S3, an SSH box) binds to a **stored connection** (the connection catalog / `PROVIDER_CATALOG`, ADR-0033 — creds as references). "Use Qdrant" = pick a `qdrant` connection from a dropdown, not paste a URL into the profile. This unifies the connection axis (#68/#70) with the backend configurator: the connection catalog is where secrets live; the profile is where a capability is *bound* to one.

### 4. Doctor validates pack needs against the environment (fail-closed with remediation)

When a pack that declares `requires = ["vector.search", "memory", ...]` is installed/enabled into an environment with no matching backend provisioned, the console shows **"needs a RAG/memory backend — none enabled here [Enable]"** (the ADR-0046 Capabilities-lens "backed by / enable one" state), and a run that reaches an unprovisioned capability **fails closed with that remediation** — never a silent skip. Doctor gains a capability-vs-environment check.

### 5. Memory: provisioned-then-mandatory (flip the current default)

Today memory is always-on and per-skill-opt-out. Flip it:

- **Provisioning = the gate.** If the environment enables memory + binds a backend, memory is available; if not, packs that `requires.memory` get the doctor warning and auto-capture is off.
- **Two uses, kept distinct:** (a) *explicit* — packs call `memory/search`/`memory/write` as steps (incident recall, training remember-run), pack-declared like RAG; (b) *automatic episodic capture* — a **lifecycle guarantee**: when memory is enabled in the environment, every run's outcome is written to episodic memory, **mandatory** (no per-skill silent opt-out).
- The `memory_enabled` skill flag is retained for genuinely memory-free skills but is no longer the enablement mechanism; the environment is.
- **LangGraph `BaseStore` (#170) is NOT adopted** — the custom `MemoryStore` Protocol already does semantic recall across sqlite/pg/qdrant and is wired; `BaseStore` is a deferred nice-to-have, not a blocker.

### 6. Parsers and eval arrive as operators, selectable through the form

- **markitdown + docling** become **parser backends inside a RAG parse/ingest operator** (the first concrete slice of #39 — move RAG parse out of engine core), each an optional extra with a deterministic fallback (the "use production libs + hermetic fallback" rule). The parser choice is a **dropdown in the configurator** (§1). This keeps engine core thin and the parser swappable/installable like any operator (ADR-0042 holds — one verb, no new kind).
- **ragas** is a separate **eval operator** (`rag/eval`) feeding the pilot/eval ledger (#77) — a quality concern, not ingestion.

### 7. Real triggers: a schema-driven form over `TriggerSpec`, YAML retained

The trigger create/edit form is generated from the existing `TriggerSpec` schema (source dropdown, template picker, HMAC secret-ref, normalize mapping) and writes the **same stored spec** the YAML editor writes (`POST /ui/api/triggers`) — form and YAML are two renderers over one artifact. **Vendor presets** (Slack, PagerDuty) are pre-filled forms that carry the vendor's normalize mapping + signature scheme — the surface that makes the missing vendor receivers (#196/#197) usable.

### 8. OAuth: Authlib is the sole shipped broker

Collapse the broker seam (ADR-0037) to **Authlib only** — keep the `OAuthBroker` Protocol, make Authlib the default and only shipped impl, remove Nango from the shipped path. Wire and **prove one real SaaS OAuth end-to-end in the UI** (recommend Slack: real `providers.yaml` entry, client-cred secret-ref, a clean *not-configured → authorize → connected → usable* state machine). The catalog then scales by data. (This amends ADR-0037's "Nango as impl #1".)

## What this is NOT

- **Not** a new executor kind or axis (ADR-0042 §4 untouched); backends stay behind the store abstractions + connections.
- **Not** a rebuild of stores/brokers/pipelines — pgvector/sqlite-vec/episodic/Authlib/LlamaIndex-ingest all exist; this ADR is the *control surface* + the memory-flip + the parser/eval operators.
- **Not** a new form framework — the UIContract renderer (#109) generates the profile form and the trigger form.
- **Not** NATS-as-a-bus — the notification `Bus` stays InProcess (Postgres/Redis deferred); NATS remains the substrate for the trigger inbox + remote-job channel only (#59).

## Consequences

- Every runtime capability becomes **configurable from one Environment form** with defaults shown, help text, and safe zero-config defaults (sqlite/inprocess/off) preserved.
- Packs stay backend-agnostic; swapping a backend is a rebind + connection change, no pack edits.
- The env-var path remains for headless/CI deploys; the profile schema is the documented superset.
- Memory stops being a silent always-on write and becomes an explicit, provisioned lifecycle guarantee.
- Two capabilities still require **live infrastructure to verify** and are tracked as their own sub-issues: NATS (docker broker, testable locally) and remote SSH/docker exec (#178, needs a real box).

## Open questions (resolve before Accepted)

- **Per-workspace vs per-profile binding.** Workspaces are first-class (ADR-0051). Is a backend bound per environment/profile, per workspace, or a workspace-scoped environment? Lean: workspace-scoped environment record.
- **Vocabulary reconciliation** (carried from ADR-0046): `rag.search` vs `vector.search`, `storage.*` vs `object.*` — pick one canonical set, alias the rest, before the doctor `requires` check ships.
- **Memory backend independence.** Memory currently shares `RAG_VECTOR_STORE`; should it get its own backend field, or continue to share the vector store? Lean: own field, defaulting to the RAG store.
- **Parser-operator boundary.** Does the RAG parse operator subsume the whole ingest pipeline (full #39 move out of core), or only the parse/reader stage first? Lean: parse stage first, full move staged.
