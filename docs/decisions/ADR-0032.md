# notify.sink — move the Slack notifier out of core to a bound service-provider

## Context

`core/notifier.py` shipped a `SlackNotifier` (httpx webhook + Slack-MCP
`slack_post` + an incident-shaped `_slack_digest`). That is **vendor code in
core** — the ADR-0028 "vendor-in-core debt" backlog item. `default_notifiers()`
constructed it whenever a Slack MCP server or `SLACK_WEBHOOK_URL` was detected
in the environment.

The engine already has the right seam for swappable providers: profile bindings
resolve a capability to a provider operator (`redact.text`, `audit.sink`).
Notifications should use the same mechanism.

## Decision

1. **Core keeps the generic mechanism, not the vendor.** `core/notifier.py`
   retains the `Notifier` protocol, `NotifierRegistry`, and the
   non-vendor `StdoutNotifier` + `FileNotifier` (the latter feeds the Claude
   inbox integration). `SlackNotifier`, `_slack_digest`, and the `httpx`/Slack
   imports are **removed**.

2. **Slack ships as a service-provider operator** — `operator-notify-slack`
   provides capability **`notify.sink`** (`notify/slack`). Dual-interface like
   `operator-audit-store`: `notify(result)` (the Notifier path) and
   `run(inp, ctx)` (a template node that posts an explicit message). It keeps
   the old delivery order (Slack MCP → webhook → no-op) and reuses the substrate
   `slack_post`; the digest is now **pack-agnostic** (reads `RunResult.raw_output`
   — summary / verdict — not incident fields).

3. **Binding, not env-detection.** `default_notifiers()` resolves the active
   profile's `[profile.bindings]` `notify.sink` (mirroring `get_audit_sink`):
   bound → the provider is appended to stdout+file; unbound → no external
   notifier. **Behavior change:** Slack is now opt-in via an explicit binding
   rather than auto-attached when `SLACK_WEBHOOK_URL`/MCP is detected. This
   matches how `audit.sink` is opt-in and keeps the default (no binding) free of
   any vendor.

```toml
[profile.bindings]
"notify.sink" = "notify/slack"
```

## Consequences

- No vendor (Slack) code in core; swapping to another channel (Teams, PagerDuty,
  email) is a new `operator-notify-*` + a binding, zero core change.
- The `Notifier` registry stays (notifications are fan-out: stdout + file +
  the bound external sink), distinct from single-bound seams like `audit.sink`.
- The substrate `services/mcp/client.slack_post` convenience remains (it's MCP
  substrate, not core-notifier debt); folding it into the bundle is a later,
  smaller item.
- Resolution is fail-open: a misconfigured `notify.sink` binding logs and
  degrades to stdout+file, never breaking a run.
