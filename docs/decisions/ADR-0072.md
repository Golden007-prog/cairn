# ADR-0072 — Dry-run as a live preflight verdict, and the governed playground

Status: Proposed (2026-07-13)
Relates to: ADR-0047 (run provenance), ADR-0067 (`cairn ask` / UIContract),
ADR-0068/0070/0071 (config surface, scoping, presets), #304 (doctor: pack
requires vs provisioned), #744 (run-submit config preflight, fail-closed), the
connection probe (`connection_probe.probe_connection`, ADR-0072 reuses it), and
the console Run/dry-run surfaces (#783).

## Context

Today "dry-run" is a **static render** of the plan from the already-fetched
UIContract: operators-per-capability, gates, cost, the command (#783). It calls
nothing and returns no verdict — it shows the *shape* of a run, not whether the
run *can actually happen*. The user's words: *"it just shows a plan, does
nothing."*

Meanwhile the checks that WOULD answer "can this run?" already exist, scattered:
- input validation (`POST /packs/{ref}/validate` — `coerce_and_validate`),
- operator/capability resolution + pack-requires check (#304 doctor),
- connection/credential reachability (the connection probe, ADR-0072-adjacent),
- config/policy preflight (#744, fail-closed),
- cost estimate + gates + approvals (UIContract `plan`),
- resolved config incl. the selected preset (ADR-0071).

And the passive **"Before you run" rail** on the Run tab already *displays* some
of this (capabilities ✓/⚠, gates, remediation) — but it's status chips, not a
single honest "ready / blocked" answer.

Separately, "playground" is used two ways and must be disambiguated:
1. a **governed compose-and-preview loop** for a real run (cairn's fit), and
2. a **LiteLLM-style model chat** playground (different surface, deferred).

## Decision

### 1. Dry-run becomes a live, side-effect-free **preflight verdict**

`dry-run` runs every check that has **no side effects** and returns a structured
verdict — the Terraform-`plan` / `kubectl --dry-run=server` analog:

```
verdict = {
  ready: bool,
  blockers: [{ kind, what, fix }],        # input-missing, cap-exceeded, not-connected, policy-deny, unresolved-operator
  cost: { min, max, cap, note },
  gates: [{ step, needs_approval }],
  resolved_config: { preset, values },    # ADR-0071 preset applied
  inputs_echoed: {...},
}
```

Composed from existing, side-effect-free pieces:
- **inputs** → `/validate` (would it 422?)
- **operators/capabilities** → resolution + pack-requires (#304)
- **connections/creds** → the **connection probe** for each required provider (reuse ADR-0072 sibling work / `probe_connection`)
- **config/policy** → the #744 run-submit preflight (fail-closed), config resolved with the selected preset
- **cost + gates + approvals** → from the compiled plan

Output is a single **✅ Ready** (with cost + which gates pause) or **❌ Blocked**
(with per-blocker one-click fixes: *"`OPENAI_API_KEY` not connected → Connect"*,
*"input `path` required"*). No run row, no spend, no external writes.

### 2. The playground IS the iterative dry-run loop

One surface, not a new concept: **edit inputs / config / preset → re-run dry-run
→ watch the verdict + cost + gates update → "Promote to run"** when green. The
passive "Before you run" rail folds INTO this verdict (one honest answer, not
scattered chips). This is cairn's governed playground.

Explicitly **out of scope** here: the LiteLLM-style model-chat playground (a
separate surface with no governance rail). Deferred, tracked separately.

### 3. Parity across surfaces

The same verdict powers the console Run tab, `cairn run --dry-run` / `cairn
preflight <ref>` (CLI), and the `cairn ask` plan step. One preflight, many faces.

## Consequences

- Dry-run answers "will this run, what will it cost, what pauses for me, what's
  blocking" — the honest pre-run gate, not decoration.
- Reuses everything already built (validate, doctor, connection probe, config
  preflight, contract plan) — mostly composition, little net-new logic.
- The verdict is the natural home for the ADR-0071 preset selection and the
  first-run/readiness story — one place to see "am I ready?"
- Must stay strictly side-effect-free (no run row, no spend, no external calls
  beyond read-only auth probes) — that invariant is the whole value.

## Rollout (see epic + slices)

MVP: a preflight endpoint that composes the checks into a verdict + the console
"ready/blocked" panel replacing the static plan + CLI parity. Then the iterative
"Promote to run" loop. Defer: the model-chat playground.
