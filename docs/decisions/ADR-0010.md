### 24.10 Decision: async messaging — `Bus` Protocol with tiered backends

**Today's situation.** Async communication concerns are scattered:

| Concern | Today's mechanism |
|---|---|
| Per-run trace events | `EventSink` write-only, drained to `SqliteInvestigationStore` / JSONL |
| Pack-to-pack (sequential) | Cascade chains (`chain_skill: X` — tight coupling) |
| Pack-to-pack (fan-out) | Not supported (§24.3.7 reserved the slot) |
| External notifications (Slack, email) | `Notifier` seam — outbound only, not subscribe-able |
| Internal work distribution | `RunDispatcher` (asyncio + concurrency lanes — in-process only) |
| Cross-process / cross-node messaging | Not supported |
| Browser/SSE clients listening to engine | Not supported |

That's the sprawl. Adding Redis as a default would just shift it.

**Decision: one `Bus` Protocol, three backends, picked by env. Same
tiered pattern as §24.4 storage — no required new infra in defaults.**

#### 24.10.1 The Protocol

```python
class Message(BaseModel):
    topic: str
    payload: dict[str, Any]
    ts: datetime
    publisher: Optional[str] = None   # pack name when known
    correlation_id: Optional[str] = None   # run_id, session_id, etc.

class Subscription:
    """Returned by subscribe(); call unsubscribe() to detach."""
    def unsubscribe(self) -> None: ...

class Bus(Protocol):
    """Single abstraction for events, notifications, and work signals."""

    async def publish(self, topic: str, payload: dict[str, Any],
                      *, publisher: Optional[str] = None,
                      correlation_id: Optional[str] = None) -> None: ...

    async def subscribe(
        self,
        topic: str | list[str],     # exact or wildcard ("incident.*")
        handler: Callable[[Message], Awaitable[None]],
    ) -> Subscription: ...

    # Optional persistence — only Tier 2 / Tier 3 backends implement.
    async def replay(self, topic: str, since: datetime
                     ) -> AsyncIterator[Message]:
        raise NotImplementedError
```

Topics use dotted hierarchy: `incident.rca_completed`, `engine.skill.started`,
`action.executed`. Wildcards (`incident.*`) match by prefix. Topic
naming is convention; the bus enforces uniqueness only when subscribing
with an explicit subject.

#### 24.10.2 Tiered backends

| Tier | Backend | New infra | Persistence | Cross-process | Use when |
|---|---|---|---|---|---|
| **1 (dev default)** | **InProcessBus** — asyncio.Queue subscribers + dispatch loop | 0 | No | No | Single-process dev/test; most single-node prod. Zero ops cost. |
| **2 (prod default)** | **PostgresBus** — `LISTEN/NOTIFY` for live delivery + `bus_events` table for replay | 0 new (reuses §24.4 Postgres) | Yes | Yes | Real deployment with §24.4 prod storage. **Same DB, no separate operational concern.** |
| **3 (optional)** | **RedisBus** — Streams (with consumer groups + replay) or pub/sub (lossy, fast) | 1 (Redis) | Streams: yes | Yes | High-throughput (>1k msg/s sustained), multi-region, or already-on-Redis shops |

Configured via env, matching §24.4's pattern:

```
OBS_BUS=inprocess                          # default if unset
OBS_BUS=postgres://...                     # prod: reuses storage Postgres
OBS_BUS=redis://localhost:6379             # Tier 3
```

When unset, defaults to whatever's reasonable for the active storage
tier (storage=postgres → bus=postgres; storage=sqlite → bus=inprocess).

#### 24.10.3 The `bus_events` table (Tier 2)

```sql
CREATE TABLE bus_events (
  id              BIGSERIAL PRIMARY KEY,
  topic           TEXT NOT NULL,
  payload         JSONB NOT NULL,
  publisher       TEXT,
  correlation_id  TEXT,
  published_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX bus_events_topic_idx ON bus_events(topic, published_at);
CREATE INDEX bus_events_corr_idx  ON bus_events(correlation_id);
```

`LISTEN bus_<sanitized_topic>` for live delivery; rows in the table
serve replay. Retention policy is operator config (default: 7 days, then
prune). The 8 KB `NOTIFY` payload limit means we send `{id}` only on
NOTIFY; subscribers fetch the row by id — keeps large payloads off the
notification path.

#### 24.10.4 Convergence — one mechanism for three concerns

The Bus is the unification of three things previously separate:

| Previously | After §24.10 |
|---|---|
| Engine emits to `EventSink` (write-only) | Engine emits to `Bus.publish("engine.skill.started", ...)`. EventSink wraps Bus subscribe → write to storage. |
| §24.3.7 cross-pack event bus (reserved, unbuilt) | Pack skills subscribe via `subscribes_to: ["incident.rca_completed"]`. Engine dispatches Bus messages to matching skills. |
| `Notifier` outbound channels | Notifier publishes to `notification.<channel>` topics; channel adapters subscribe. Pack code never holds Slack clients. |

This means:
- **One mechanism to learn** for async messaging across the platform
- **Trace storage and event bus are the same stream**, viewed two ways
  (storage = subscriber that persists; live UI = subscriber that
  streams to a WebSocket)
- **Subscribers can be pack skills, storage handlers, external
  webhooks, or in-process callbacks** — all use the same `Bus.subscribe`

#### 24.10.5 What this unlocks

| Use case | Backend needed |
|---|---|
| Pack A → Pack B notification (single process) | Tier 1+ |
| Cross-pack fan-out (incident.rca_completed → 5 packs subscribe) | Tier 1+ |
| Cross-process worker dispatch | Tier 2+ |
| Browser/SSE clients see live run timeline | Tier 2+ (LISTEN over WebSocket) |
| Durable replay of past events | Tier 2+ |
| External webhook subscribers | Tier 2+ |
| Sustained 10k+ msg/sec | Tier 3 only |
| Multi-region | Tier 3 only |

#### 24.10.6 What this does NOT do (honest limits)

- **Not a queue with strict at-least-once delivery** for InProcessBus.
  If the subscriber's handler raises, the message is lost (logged but
  not retried). For at-least-once semantics, use Tier 2/3 with the
  `replay` API + a `last_processed_id` tracker on the subscriber side.
- **Not a workflow engine.** For multi-step durable processes (HITL
  approval → execute → rollback), use Temporal child workflows
  (§24.2). The Bus is for *notifications*, not orchestration.
- **No request/response.** Bus is fire-and-forget. If pack A needs an
  answer from pack B, that's a capability call (§24.3), not an event.

| Sub-phase | What | When |
|---|---|---|
| **P3.b** | Bus Protocol + InProcessBus + EventSink convergence | Bundled with P3 (workflow consolidation — same touch surface) |
| **P3.c** | Skill `subscribes_to:` + dispatcher closure of §24.3.7 | Same as P3.b |

(was ~24, ~27 with separate event-bus runtime).

#### 24.10.9 Harvested concretes (from the `event-bus.md` draft, now deleted)

The draft's three load-bearing details, kept here as the build spec:

**EventEnvelope** — one normalized shape for every runtime event:
```json
{
  "event_id": "evt_123", "run_id": "run_456", "seq": 42,
  "timestamp": "2026-06-11T10:00:00Z", "type": "node.completed",
  "pack": "incident", "template": "incident-rca", "node": "synthesize",
  "payload": {}, "visibility": "standard"
}
```
`seq` is **required** — per-run monotonic — so a UI client can reconnect and
request missed events. (Aligns with the existing `cairn/core/storage`
subscriber + `seq` and `obs/events.py` append-only sink.)

**Transactional outbox** — durability without an engine: in one DB
transaction, insert the event into `run_events` *and* a row into
`event_outbox`; commit; a publisher drains unpublished rows to the
local/NATS/Redis bus and marks them published. If the bus is down the
replay store still holds the event — the bus is live-delivery only, never
source of truth.

**Subject naming** (when a real broker lands): `agentops.runs.<run_id>.events`,
`agentops.rag.<index_id>.events`, `agentops.workers.<worker_id>.heartbeat`,
`agentops.approvals.<approval_id>.events`. NATS (Apache-2.0) / Valkey (BSD) /
Kafka (Apache-2.0) all permissive; the bus stays **optional** — core works
without it.

#### 24.10.10 P3.b — DONE 2026-06-12 (Bus Protocol + InProcessBus + additive bridge)

- `cairn/core/bus/__init__.py` — `Message` (topic/payload/ts/publisher/
  correlation_id), `Subscription` (per-sub asyncio.Queue + consumer task),
  `Bus` Protocol, `InProcessBus` (wildcard prefix dispatch `incident.*` / `*`;
  at-most-once — a raising handler logs + drops per §24.10.6; `replay` raises
  `NotImplementedError`, Tier-2+ only), `get_bus()` factory on `OBS_BUS`
  (default `inprocess`; `postgres://`/`redis://` degrade to InProcessBus with a
  loud log — the bus is optional, core works without a broker).
- **Convergence — additive bridge (decided over full inversion).** The
  existing run-event path (`RunStore.append_event` → `_EventHub` →
  `subscribe` → SSE `/runs/{id}/stream`) is **untouched**. A new
  `RunDispatcher._emit(run_id, type, data)` records the event AND publishes it
  to the bus on `run.<type>` (`correlation_id=run_id`); all dispatcher run-event
  sites (queued/running/done/cancelled/failed) + the runner's `_sink` route
  through it. Both legs are best-effort — neither logging nor the bus can break
  a run. Rationale: full inversion (engine→bus→storage-subscribes) would
  refactor the SSE hot path + its tests for no present-day consumer beyond what
  the additive bridge already provides; revisit at P5.b when PostgresBus +
  cross-process delivery land.
- **Deferred (not P3.b):** `Notifier`→bus convergence; `EventEnvelope` +
  transactional outbox (Tier-2 / P5.b); PostgresBus (P5.b); RedisBus (P7.b). The
  richer `EventEnvelope` shape (pack/template/node/visibility) lands with Tier-2
  where cross-pack routing needs it; today's `Message` is the Protocol-faithful
  shape.

#### 24.10.11 P3.c — DONE 2026-06-12 (skill `subscribes_to:`, closes §24.3.7)

- `TriggersSpec.subscribes_to: list[str]` (bus topic patterns) + `TriggerEvent`
  gains `source="event"` + a `match_skill_to_event` branch matching the event's
  topic against `subscribes_to` via the bus wildcard matcher.
- `cairn/core/dispatch/bus_bridge.py` — `BusSkillBridge` (sibling to
  `SkillScheduler`): at start it subscribes to the union of loaded skills'
  `subscribes_to` topics; on a message it submits a `source="event"`
  `TriggerEvent` on the background lane, and the engine routes it to the precise
  subscribing skills. Wired into `build_app` startup/shutdown (inert when no
  skill subscribes). Defensive when the runner exposes no skill engine.
- **Loop guard:** the engine's own `run.*` lifecycle firehose (which the P3.b
  bridge publishes) is **reserved** — `BusSkillBridge` drops `run.*` messages so
  a skill can't self-trigger on its own run events. `subscribes_to` is for
  cross-pack *domain* topics a pack publishes explicitly (e.g.
  `incident.rca_completed`); no pack publishes such topics yet, so the bridge is
  mechanism-complete but consumer-light until a second pack lands.
