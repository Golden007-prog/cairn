# Runtime durability tiers — `in_process` · `dbos` · `temporal`

> **Amended by [ADR-0036](ADR-0036.md) (2026-06-18):** `dbos` is no longer a
> graph-wrapping runtime tier. Durable governed templates run on **Temporal**
> (dev = `in_process`); `dbos` becomes a **batch-executor tier** for
> data-parallel jobs. The `dbos` rows in the matrix below are superseded for
> running templates — root cause: the #41 reentrant-loop deadlock.

## Context

cairn must run governed agentic workflows that can last **hours or days**
(HITL pauses, long training/eval jobs) and survive crashes — **without forcing
every deployment onto a heavy Temporal cluster.**

Research (June 2026) established the key distinction: **a checkpointer makes
*state* durable, not *execution*.** LangGraph's `PostgresSaver`/`SqliteSaver`
persists graph state per super-step, but the OSS library has *"no task queue, no
worker pool; if the process dies, everything dies with it… you must detect the
failure yourself and re-invoke."* Durable execution needs a **liveness layer**:
crash-detection, automatic resume, single-active coordination, timers. "Checkpoints
are not durable execution."

Options evaluated:
- **Build the liveness layer ourselves** — rejected (`/verify-upstream`: the
  ecosystem already ships it).
- **Temporal** — full server-side liveness + multi-node leasing, but a heavy
  cluster. We have it working (LangGraph plugin; SQLite-persistence keystone
  verified, #27).
- **DBOS Transact** — MIT **library** (no server), backed by **SQLite or
  Postgres**, automatic crash-recovery (scans `PENDING` on restart; workflow ID
  = idempotency key). Validated by Pydantic AI's first-class DBOS integration
  (wrapper + chokepoint-steps pattern).
- **NATS** — durable *messaging* substrate (streams/KV/scheduler), **not** an
  execution engine → belongs to the event-bus decision (#14), not here.
- **Hatchet** — MIT but a separate server; fallback, not chosen.
- **Restate** — already rejected (ADR-0024).

## Decision

### `OBS_RUNTIME ∈ { in_process, dbos, temporal }`

This extends the prior `{in_process, temporal}` set with **`dbos`** as the
default durable tier.

| Env / shape | `OBS_RUNTIME` | Liveness engine | System + checkpointer DB | Concurrency |
|---|---|---|---|---|
| dev / local | `dbos` | DBOS (library, no server) | **SQLite** file | single process |
| prod — standard / single-box | `dbos` | DBOS (library, no server) | **Postgres** | **single orchestrator process** |
| prod — scale / HA / multi-node | `temporal` | Temporal (cluster, server-side leasing) | **Postgres** | multi-worker, leased |
| test / ephemeral | `in_process` | none (crash loses the run) | memory / SQLite | — |

### The boundary is concurrency, not environment

DBOS OSS is **single-node-safe**: recovery works by scanning `PENDING`
workflows on restart, and one process owning its workflows is correct. Running
**multiple orchestrator replicas** against the same DB risks double-execution
(*"both processes may execute the step"*) unless coordinated by DBOS **Conductor**
(commercial, out of scope) — that is exactly the line where you move to
**Temporal** (server-side leasing). **A single-box prod never needs Temporal.**

### Three orthogonal axes — do not conflate

1. **Checkpointer (LangGraph)** = graph **state**. Present in *every* tier
   (SQLite dev / Postgres prod), sitting *under* the liveness engine.
2. **Liveness engine** = execution recovery: none (`in_process`) / DBOS
   (single-node) / Temporal (multi-node).
3. **Executor axis** (`in_process · mcp_tool · docker · kubernetes_job ·
   remote_job · http_call`, ADR-0026) = durable **long-running work**,
   **orthogonal to the runtime tier**. Hours/days workflows work in *any* tier
   because the long work lives in the executor; the runtime only has to recover
   the *orchestration*, which a single-process restart handles.
4. **Event bus (NATS, #14)** = transport / timers substrate, a *separate*
   decision — never the execution engine.

The same compiled LangGraph graph runs under all tiers; only the runtime adapter
swaps. Migration `dbos → temporal` = change `OBS_RUNTIME`, keep the same Postgres
+ checkpointer.

## Consequences

- **DBOS-on-SQLite supersedes Temporal-on-SQLite (#27) as the dev durable
  default** — strictly lighter (a library + a file, *no* Temporal server
  process). The Temporal-on-SQLite keystone result (#27) stays in the record as a
  **proven fallback**, not the default.
- **New build: the `dbos` runtime adapter** (spike #31) — wrap the run as a
  `@DBOS.workflow`; decorate the existing chokepoints `invoke_operator` /
  `llm_complete` / `mcp/call` as `@DBOS.step`. Constraints surfaced by Pydantic
  AI's integration, to honour:
  - state must be **pickle-serializable and small (~<2 MB)** (main risk for large
    LangGraph state);
  - **no streaming inside a workflow** — stream via the event store / SSE replay;
  - use **DBOS `StepConfig` retries**, not *also* our per-operator `RetryPolicy`
    (avoid double-retry);
  - **unique workflow name** per template (name + sha) for correct recovery;
  - workflow body must be **deterministic** (same discipline as Temporal).
- **Prod DB tier is shared** by `dbos` and `temporal` — one Postgres (#29).
- DBOS is a **younger dependency** than Temporal; acceptable for the single-node
  tier, re-evaluate for HA.
