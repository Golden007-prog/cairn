# ADR-0066 — Bundles carry the cross-pack data contract; packs are standalone typed steps

Status: Proposed (2026-07-07)
Relates to: ADR-0045 / #209 (registry + bundle distribution), ADR-0047 (run
provenance + content-addressed schema store), ADR-0059 + `docs/ideas/data-processing-pipeline-2026-07-04.md`
(governed data pipeline), the `finetune` template (`cairn/packs/training/templates/finetune.md`),
the `subgraph_node` composition path (`core/engine/compiler.py`), and the bundle
manifests (`cairn-registry/bundles/*/bundle.toml`). Supersedes the "compose a
sibling pack as a subgraph inside the flagship template" pattern for *cross-pack*
pipelines.

## Context

The flagship `finetune` template composes the `dataset-readiness/check` template
as a `subgraph_node` (cross-pack). Reading the actual bindings surfaces two
coupled problems:

1. **Training hard-depends on the dataset pack.** `subgraph_node` resolves the
   referenced template **at compile time**; with the dataset pack (or its
   `obs-operator-dataset-checks`) absent, `compile_template(finetune)` raises
   `FileNotFoundError` / `UnknownOperatorError`. So you cannot `cairn run finetune`
   — or point the console/CLI at a dataset and just train — without installing a
   *dataset-validation* pack. Training is not dataset-source-agnostic.

2. **The "composition" carries no data.** `dataset-readiness` outputs **only a
   verdict** (`ReadinessReport`: `verdict / summary / blocking / warnings`), and
   `run-train` reads the **raw** `$input.dataset_path`. The gate and the train
   step are coupled *only by co-reading the same input path* — there is no
   data-flow (gate output → train input). The dataset is never "produced" by the
   gate and "injected" into training; both just read the user's path.

The intended usage is the opposite of what the coupling forces:

- **Direct train** (CLI / web console): *point at a dataset* (S3/HF/local) and
  train. No dataset pack required.
- **Governed pipeline**: the dataset pack validates/curates a dataset and
  **its output** (an S3/HF ref) is injected into training. Governance ("must go
  through the gate") is an *environment/policy* decision, not a property baked
  into the only training template.

Today the composition lives **inside a template** (hardcoded `subgraph_node`).
There is no layer that lets independent packs be wired by a typed data contract.
`bundle.toml` is thin — `template_packs + profile` only (operators auto-resolved
from `composes`); it does not express *how packs connect*.

## Decision

**The bundle is the unit of composition AND deployment. It carries the cross-pack
*data contract*. Packs are standalone, typed steps that never reference each
other.**

1. **Packs are standalone + typed.** Each template exposes a typed I/O contract
   (its `input_schema` → `output_schema`, already content-addressed per ADR-0047).
   `training` ships a first-class **`train`** template: `FinetuneRequest(dataset_path, …)
   → FinetuneReport`, runnable on its own. `dataset-readiness` gains a
   **`dataset_uri`** output (the validated/curated dataset location — S3/HF), so it
   can *feed* a downstream step, not just gate. No template references a sibling pack.

2. **The bundle declares the data contract** (steps + typed output→input bindings
   + governance gates) in `bundle.toml`:

   ```toml
   [bundle.contents]
   template_packs = ["dataset-readiness", "training"]

   [[bundle.pipeline]]
   name = "governed-finetune"
     [[bundle.pipeline.step]]
     id = "gate"; pack = "dataset-readiness"; template = "check"
     inputs = { path = "$input.dataset_path" }
     [[bundle.pipeline.step]]
     id = "train"; pack = "training"; template = "train"
     gate   = "$steps.gate.verdict == 'pass'"                    # governance, declarative
     inputs = { dataset_path = "$steps.gate.dataset_uri" }       # ← the injection (S3/HF)
   ```

   The wiring lives in the **bundle**, not in any pack.

3. **The engine compiles a bundle pipeline → a graph directly** (chosen over
   "lower the bundle into a generated template"). A new compile target reads
   `[[bundle.pipeline]]`, treats each step as a node, and **validates the contract
   at compile time**: every `$steps.<id>.<field>` binding must resolve to a real
   field of that step's *output schema*, and its type must be compatible with the
   target step's *input schema* field. A type-incompatible wire fails the bundle
   compile — that is what makes it a **contract**, not just a wire. (Reuses the
   ADR-0047 schema store for the field/type lookups.)

4. **`train` is ungated by default; governance opts in via policy.**
   `cairn run train --dataset …` just trains. An **environment policy** can
   *require* the readiness gate before training in prod (e.g. deny `train` unless
   preceded by a `dataset-readiness` step whose verdict is `pass`). Governance is
   an environment concern, enforced by policy — never by making a template's gate
   un-skippable.

5. **The bundle is deployed as a unit** — packs + data contract + profile →
   `cairn.lock` / image (the ADR-0045 / #209 materializer already consumes the
   resolved composition; it gains the `[[bundle.pipeline]]` contract).

### What runs where

| Concern | Before | After |
|---|---|---|
| Cross-pack composition | hardcoded `subgraph_node` in `finetune` | declarative `[[bundle.pipeline]]` contract |
| Direct `train` on a dataset | ❌ requires the dataset pack | ✅ standalone, dataset-source-agnostic |
| dataset → train data-flow | ❌ both re-read raw `$input.dataset_path` | ✅ gate **outputs** `dataset_uri`, injected into train |
| "must gate before train" | un-skippable subgraph | **environment policy** |
| Deploy unit | packs (bundle = thin install list) | bundle = packs + contract + profile |

`subgraph_node` is **retained for *within-pack*** composition (a pack embedding
its own sub-flow); it is no longer the mechanism for *cross-pack* pipelines.

## Phased plan

**Phase 1 — Decouple (this ADR's first cut; no new engine).** Ships the value now:
- `training`: promote a first-class standalone **`train`** template (dataset-source-agnostic; `train-remote-smoke` is effectively this today, mislabeled).
- `dataset-readiness`: add a **`dataset_uri`** output to the gate/curate step.
- Drop the hard `subgraph_node` dataset dependency from the standalone train path; keep the current `finetune` template working (as the interim composed pipeline) until Phase 2.
- Governance-by-policy: an environment policy that can require the gate before train.

**Phase 2 — Bundle-pipeline compiler (follow-up epic).**
- `[[bundle.pipeline]]` schema in `bundle.toml`.
- Engine compile target: bundle contract → graph, with compile-time typed-contract validation (output-field ↔ input-field type match).
- Move `governed-finetune` from a template `subgraph_node` to a bundle pipeline; deprecate the cross-pack subgraph in the flagship template.
- Materializer (#209) consumes the contract.

## Consequences

- **Packs become genuinely reusable.** `training` works standalone and can be
  wired after *any* dataset source; `dataset-readiness` can feed any consumer.
- **Composition is explicit and typed.** The data contract is declared + validated
  at compile time, not hidden in a template's subgraph.
- **Governance is where it belongs** — policy/environment, not template structure.
- **Cost:** a new bundle-compile path (Phase 2) and a contract schema; two packs
  gain/adjust a template + an output field (Phase 1). The `finetune` template keeps
  working through the transition.
- **The 4 open PRs (#573–#576) remain valid** — they fix real bugs in the current
  model, which ships until Phase 2 lands.

## Alternatives considered

- **Keep cross-pack `subgraph_node` (status quo).** Rejected: forces the training
  pack to depend on a dataset-validation pack and provides no data-flow.
- **Lower the bundle into a generated template.** Rejected in favour of compiling
  the bundle → graph directly: a generated template re-hides the composition in a
  template artifact and inherits `subgraph_node`'s cross-pack coupling; a
  first-class bundle runnable keeps the contract declarative and inspectable.
- **Gated-by-default `train` with an `--ungoverned` escape.** Rejected: re-introduces
  a soft coupling and a template-level governance decision; policy-per-environment
  is the cleaner control point.
