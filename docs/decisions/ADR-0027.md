# Operator taxonomy

## Context

A proposal surfaced to add a third operator tier — `core | builtin | official`
— where "core operators" would be the necessary ones. This ADR settles how
operators are classified and rejects the new tier.

## Decision

### Operators are classified on TWO orthogonal axes (not one list)

- **`kind`** — what it structurally does (ADR-0026):
  - `operator` — executes a workflow node (`clickstack/query_logs`, `blast-radius/compute`)
  - `service_provider` — backs a substrate *service* the engine uses cross-cuttingly
    (memory, rag, redact, secrets, audit, authz), bound under `services.<kind>`
- **`trust_level`** — who ships it / install policy (ADR-0026 §4):
  `builtin · official · community · private · local`

An operator is *(kind, trust_level)* — e.g. `operator-redact-regex` =
`(service_provider, builtin)`.

### REJECTED: a `core` operator tier

1. It overlaps `builtin` ~entirely (`builtin` already = "ships with the engine,
   auto-installs, makes a fresh checkout work"). The only new idea is
   *necessary* — which is not a trust/distribution property.
2. **Necessity is a property of the SERVICE, not the operator.** What's
   mandatory is that *a redactor is bound* — not that one specific operator
   exists. Builtin-regex and official-Presidio redactors are interchangeable.
3. **"core operator" is an oxymoron that re-opens the door we shut** (no
   vendor/impl code in core — ADR-0024). "core" must mean *the engine*, never
   an operator, or the "just put it in `cairn/core/`" drift returns.

### Necessity = a PACK-DECLARED service requirement, doctor-enforced

Necessity is **per-pack, not a global engine mandate.** A pack declares the
substrate services IT needs via `[requires].services` / `[optional]` (the
ADR-0026 three-layer model); the deploying profile must satisfy each declared
requirement, and `doctor`/composition fails loud if a *required* (not
optional) service is left unbound. Any provider (builtin or official)
satisfies it.

There is **no unconditional "every deployment must bind X" list.** In
particular the safety services (`redact` / `secrets` / `audit` / `authz`) are
**optional / pack-declared, not universally required** — see ADR-0028. A pack
that touches sensitive data declares it needs `redact`; a pack on synthetic
data declares nothing and the service stays a no-op. "Substrate-critical"
(below) describes which operators *ship as builtins*, not a set every
deployment is forced to run.

### Directory split: `builtins/` (substrate) vs `official/` (add-ons)

Finish the split already scaffolded (`cairn/operators/official/` exists but
is empty today):

- **`cairn/operators/builtins/`** — substrate-critical service providers that
  back required services and auto-install, zero-dep: `mcp`, `memory_local`,
  `artifact_local`, `rag_local` (+ future `redact_regex`, `secrets_env`,
  `audit_store`, `authz_static`).
- **`cairn/operators/official/`** — optional add-ons (domain + vendor),
  opt-in: move `clickstack`, `git`, `blast_radius`, `postmortem` here; future
  `presidio`, `openbao`, `cerbos` land here too.

The directory layout *becomes* the "necessary vs optional" split, using the
existing two tiers — no sixth tier.

## Consequences / backlog

- **Refactor (backlog):** move the four incident-domain operators from
  `builtins/operators/` → `official/operators/`; update entry-points, profile
  bindings (`local-dev.toml`), and tests. Mechanical, name-stable.
- Engine gains a `requires.services` declaration + doctor check for unbound
  required services.
- **Security guardrail (gated, not yet active):** of the five trust levels,
  `community` is the only one that would execute operator code the deployer did
  not author. **Before the community channel is ever enabled for execution,
  community-trust operators MUST run sandboxed** — `nsjail` / gVisor / container
  isolation via the `docker` / `kubernetes_job` executor — never in-process.
  Today no community channel executes (live channels are builtin/official/
  private/local, all author-trusted), so there is nothing to sandbox; this
  records the precondition at the decision point so it fires when someone
  proposes turning the channel on, rather than rotting as a standalone issue.
